## Критические уязвимости

### 1. Отключенная TLS верификация (CRITICAL) — ИСПРАВЛЕНО ✅

**Файл:** `api/mintrud_api.py`, `api/mintrud_api_httpx.py`, `api/mintrud_api_urllib.py`, `utils/proxy_manager.py`

```python
# TLS verification can be toggled via checkbox in UI
ENABLE_TLS_VERIFY = False  # Default: off for corporate proxies
```

**Статус:** Исправлено. TLS верификация может быть включена через чекбокс в настройках прокси. По умолчанию выключена для работы через корпоративные прокси с SSL-инспекцией.

---

### 2. Слабый механизм получения ключа шифрования (HIGH)

**Файл:** `utils/crypto.py:16-19`, `api/mintrud_api.py:39-43`

```python
def _get_derive_key():
    username = os.environ.get('USERNAME', 'default_user').encode('utf-8')
    return hashlib.sha256(username).digest()
```

**Риск:**
- Ключ привязан к имени пользователя Windows — легко угадать (обычно `Administrator`, `user`, ФИО)
- Не используется соль — возможна атака по радужным таблицам
- Любой пользователь с тем же именем может расшифровать данные

**Рекомендация:** Использовать библиотеку `keyring` для безопасного хранения ключей, применить PBKDF2 или Argon2 для деривации ключа.

---

### 3. Слабое XOR-шифрование как fallback (HIGH)

**Файл:** `utils/crypto.py:63-77`, `api/mintrud_api.py:97-118`

**Риск:** XOR с хешем — обратимо, не является криптографически стойким. Если библиотека `cryptography` недоступна — данные практически не защищены.

**Рекомендация:** Удалить XOR fallback, требовать установку `cryptography` как обязательной зависимости.

---

## Рекомендации по повышению безопасности

### Приоритет 1 — Исправить критические уязвимости

1. **Включить TLS верификацию:**
   - В `api/mintrud_api.py` заменить `verify=False` на `verify=True`
   - Для корпоративных прокси с собственным CA — использовать кастомный bundle

2. **Использовать криптографически стойкое шифрование:**
   - Отказаться от XOR fallback
   - Использовать библиотеку `keyring` для безопасного хранения ключей
   - Применять соль (salt) + PBKDF2 или Argon2 для деривации ключа

3. **Шифровать настройки прокси:**
   - Применить тот же механизм, что для API-ключа
   - Или использовать Windows Credential Manager через `keyring`

### Приоритет 2 — Защита от внутренних угроз

4. **Удалить чувствительные данные из логов:**
   ```python
   # Маскировать пароль при логировании
   safe_url = f"{proxy_host}:***"
   logger.info(f"Прокси: {safe_url}")
   ```

5. **Добавить валидацию и санитизацию ввода:**
   - СНИЛС, ИНН — проверка по контрольной сумме
   - XML — защита от XXE атак

### Приоритет 3 — Корпоративное развертывание

6. **Добавить аудит операций** — логировать кто, когда, какие действия выполнял

7. **Реализовать rate limiting** — защита от злоупотреблений API

8. **Вынести secrets в переменные окружения** или использовать Vault-решения
