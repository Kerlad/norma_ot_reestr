# Техническое задание на разработку системы контроля обучения по охране труда

## 1. Общие положения

### 1.1. Цель проекта
Создать десктопное приложение (PySide6) для учёта и контроля обучения сотрудников по охране труда в соответствии с Постановлением Правительства РФ № 2464. Приложение обеспечивает внесение данных о сотрудниках, прошедших обучение, формирование XML для передачи в реестр Минтруда (edu.rosmintrud.ru), хранение истории проверок знаний, формирование протоколов проверки знаний, а также сводный анализ статуса обучения сотрудников с возможностью запроса актуальных данных из реестра Минтруда.

### 1.2. Основные пользователи
Один пользователь с полным доступом ко всем данным и функциям приложения. Приложение не имеет встроенной системы авторизации — персональные данные защищены полевым шифрованием (Fernet + DPAPI).

### 1.3. Ограничения
- Работает на ОС Windows 10/11
- При наличии доступа к Интернету — интеграция с API Минтруда (edu.rosmintrud.ru)
- Обязательно наличие XSD-схемы в папке `schema/` для конвертации в XML
- Максимум 5000 записей в таблице workers_data
- Максимум 300 записей на один протокол (DOCX)

## 2. Функциональные требования

### 2.1. Вкладка «Внесение данных»

**Назначение:** Ввод данных УЦ и работодателя, загрузка данных сотрудников из Excel/XML, ручной ввод записей о прохождении обучения.

**2.1.1. Данные УЦ и работодателя**
- ИНН УЦ (обязательное, 10 или 12 цифр)
- Наименование УЦ (обязательное)
- ИНН Заказчика (обязательное, 10 или 12 цифр)
- Наименование Заказчика (обязательное)
- Кнопка «Сохранить данные» — данные шифруются (AES/Fernet) и сохраняются в `data/org_settings.json`
- При загрузке Excel пустые поля ИНН/наименования автоматически заполняются из сохранённых настроек

**2.1.2. Загрузка данных**
- Поддерживаемые форматы: .xlsx, .xls, .xml (RegistrySet)
- Кнопка «Выбрать файл» — открывает диалог выбора файла (QFileDialog)
- Кнопка «Загрузить файл» — запускает импорт:
  - XLSX: колонки `Фамилия | Имя | Отчество | СНИЛС | Должность | ИНН Заказчика | Наименование ЮЛ Заказчика | ИНН УЦ | Наименование УЦ | Результат | № программы | Дата | № протокола`
  - XML: парсинг RegistrySet по XSD-схеме (lxml)
  - Валидация: СНИЛС (11 цифр), программа (1–29, кроме 5), результат (Удовлетворительно / Неудовлетворительно), дата (не в будущем)
  - Поддержка нескольких программ через запятую в одной ячейке (создаётся несколько записей)
  - Если данные уже загружены — диалог: объединить (пропуская дубли по СНИЛС+программа) или заменить
- Кнопка «Создать шаблон» — генерирует .xlsx с заголовками для заполнения (openpyxl)
- Экспорт отчёта об ошибках импорта в .xlsx
- Сигнал `data_loaded.emit(records, merge_mode)` — передаёт данные на вкладку «Просмотр данных»

**2.1.3. Ввод данных работника (ручной)**
- Поля: Фамилия, Имя, Отчество, СНИЛС (11 цифр, автоформатирование в вид `123-456-789 00`), Должность, Номер программы (1–29, несколько через запятую), Номер протокола, Результат (выпадающий список: Удовлетворительно / Неудовлетворительно), Дата (ДД.ММ.ГГГГ)
- Кнопка «Справка» — показывает перечень программ (двойной клик вставляет номер)
- Кнопка «Сохранить данные» — добавляет запись
- Валидация: обязательные поля, формат СНИЛС, корректность программы, дата не в будущем

### 2.2. Вкладка «Просмотр данных»

**Назначение:** Табличное отображение загруженных/введённых данных, редактирование, удаление, конвертация в XML.

**Функционал:**
- Таблица с колонками: Фамилия, Имя, Отчество, СНИЛС, Должность, ИНН заказчика, Наименование заказчика, ИНН УЦ, Наименование УЦ, Результат, № программы, Дата, № протокола
- Многострочные заголовки таблицы
- Контекстное меню (правый клик): «Редактировать» (открывает диалог), «Удалить» (с подтверждением)
- Кнопка «Очистить» — удаляет все данные (с подтверждением)
- Кнопка «Конвертировать» — экспорт данных в XML-файл:
  - Загружает настройки организации из `org_settings.json`
  - Формирует RegistrySet XML по XSD-схеме (`schema/educated_person_import_v1.0.9.xsd`)
  - Диалог сохранения .xml

**Персистентность:**
- Данные автоматически сохраняются в `data/app_data.db` (таблица `workers_data`) при каждом изменении
- Автозагрузка при старте приложения

### 2.3. Вкладка «Передача данных»

**Назначение:** Отправка XML в Минтруд, запрос регистрационных номеров, поиск по СНИЛС.

**2.3.1. API ключ**
- Поле ввода API-ключа (32 символа, из кабинета edu.rosmintrud.ru)
- Кнопка «Сохранить ключ» — шифрованное сохранение в `data/api_key.json`
- Валидация: длина 32 символа

**2.3.2. Настройки прокси**
- Режимы: «Без прокси», «Авто (системные)» (определение через реестр Windows), «Вручную»
- При ручном режиме: URL прокси, логин, пароль (шифруется, Fernet)
- Чекбокс «Проверять TLS» (для корпоративных прокси с SSL-инспекцией)
- Поддержка NTLM, Kerberos/Negotiate, Basic-аутентификации
- Сохранение настроек прокси в зашифрованном `data/proxy_settings.json`

**2.3.3. Выбор transport backend**
- Авто (пробует requests, затем WinINET)
- Requests (библиотека requests, Windows Integrated Authentication)
- WinINET (Windows Internet API, лучшая поддержка корпоративных прокси)

**2.3.4. Отправка XML**
- Выбор XML-файла (кнопка «Выбрать XML»)
- Кнопка «Отправить XML на сервер» — формирует multipart-запрос (Request.xml + data.olot) и отправляет на `edu.rosmintrud.ru/api/set/push`
- При успехе: получение SetId, уведомление, автоматическая передача записей в «Журнал проверки знаний»
- При ошибке: отображение кода и сообщения об ошибке

**2.3.5. Запрос по SetId**
- Поле ввода SetId
- Кнопка «Запросить номера» — пагинированный запрос к `edu.rosmintrud.ru/api/GetEducatedPersonXML`
- Результат: экспорт в XLSX с колонками `Номер записи в реестре | ФИО | СНИЛС | Должность | ИНН работодателя | Наименование работодателя | Номер программы | Название программы | Номер протокола | Дата | Зачёт`
- Автоматическое обновление baseNo в «Журнале проверки знаний» (статус меняется с «pending» на «received»)

**2.3.6. Запрос по СНИЛС**
- Поле ввода СНИЛС
- Кнопка «Найти» — запрос к API по СНИЛС
- Отображение найденных записей

### 2.4. Вкладка «Журнал проверки знаний»

**Назначение:** Хранение и просмотр истории отправок XML на сервер Минтруда, отслеживание регистрационных номеров.

**Модель данных (JournalRecord):**
- `uuid` — уникальный идентификатор записи
- `send_date` — дата/время отправки
- `set_id` — идентификатор набора от сервера
- `xml_file` — путь к отправленному XML
- `last_name, first_name, middle_name` — ФИО
- `snils` — СНИЛС (формат «123-456-789 00»)
- `position` — должность
- `program_id` — номер программы («1»–«29»)
- `program_title` — название программы
- `exam_date` — дата экзамена
- `protocol` — номер протокола
- `result` — результат
- `base_no` — регистрационный номер (заполняется после запроса по SetId)
- `status` — «pending» (ожидает) / «received» (получен)

**Функционал:**
- Таблица с колонками: Дата отправки, SetId, ФИО, СНИЛС, Должность, Программа, Дата экзамена, Протокол, Результат, Рег. номер, Статус
- Цветовая индикация: «pending» — оранжевый, «received» — зелёный
- Панель фильтрации: поиск по ФИО/СНИЛС, фильтр по SetId, статусу, номеру протокола, диапазону дат отправки
- Кнопка «Сбросить» — очищает все фильтры
- Кнопка «Экспорт в XLSX» — выгрузка отфильтрованных записей
- Кнопка «Удалить» — удаление выбранных записей
- Контекстное меню: «Удалить»
- Хранение: `data/app_data.db` (таблица `exam_journal`)
- Менеджер: `JournalManager` (CRUD, поиск, фильтрация, обновление baseNo по SetId)

### 2.5. Вкладка «Протокол»

**Назначение:** Формирование протокола проверки знаний по шаблону DOCX.

**2.5.1. Данные комиссии**
- Поля: Название организации, Номер протокола, Дата проверки знаний, Номер приказа, Дата приказа
- Председатель комиссии: ФИО, Должность
- Члены комиссии (до 3): ФИО, Должность
- Представитель профсоюза: ФИО, Должность
- Кнопка «Сохранить данные комиссии» — шифрованное сохранение в `data/commission_data.json`
- Кнопка «Программы обучения» — открывает редактор программ (номер документа, часы), данные сохраняются в `data/programs_data.json`

**2.5.2. Генерация протокола**
- Выпадающий список: выбор номера протокола (из журнала) или «Все»
- При выборе номера — автозаполнение даты проверки знаний из журнала
- Кнопка «Сгенерировать протокол»:
  - Берёт данные комиссии из формы
  - Находит записи работников по номеру протокола из `JournalManager`
  - Заполняет шаблон `Protokol_proverki_znanii_OT.docx` (python-docx)
  - Сохраняет как «Протокол {номер} от {дата}.docx»
- Обязательные поля: номер протокола, название организации, номер приказа, ФИО председателя
- Группировка по ФИО (одна строка для совпадающих ФИО)

### 2.6. Вкладка «Протокол одиночного работника»

**Назначение:** Быстрое формирование протокола для одного работника с ручным вводом данных.

**Функционал:**
- Ручной ввод: ФИО, должность, программа, дата, результат
- Поддержка нескольких программ (через запятую)
- Кнопка «Справка» для выбора программ из списка
- Данные комиссии подгружаются из сохранённых на вкладке «Протокол»
- Генерация протокола по тому же шаблону DOCX
- Все поля необязательные (пустые поля = пустые в протоколе)

### 2.7. Вкладка «Сводка по сотрудникам»

**Назначение:** Расширенный анализ статуса обучения сотрудников с интеграцией с реестром Минтруда.

**Источники данных:**
- Ручной ввод данных работника
- Импорт XLSX
- API Минтруда (`get_by_snils`) — запрос актуальных данных из реестра по СНИЛС

**Ручной ввод:**
- ФИО (Фамилия + Имя + Отчество)
- СНИЛС
- Должность
- Программы направления на обучение (кнопка «Справка» — двойной клик добавляет номер)
- Кнопка «Добавить запись»
- Кнопка «Отмена» (очищает форму)

**Поля таблицы:**
- ФИО (Фамилия + Имя + Отчество)
- СНИЛС
- Должность
- Потребность в обучении по программам (скрытое поле, формат «1;2;3;6»)
- Программы обучения (выбранные пользователем колонки, макс. 6 одновременно)
  - Для каждой программы — четыре подколонки: Потребность, Дата обучения, Протокол, Рег. номер
- Статус (цветовая индикация):
  - **Не обучен** — красная заливка
  - **Обучен** — зелёная заливка
  - **Просрочено** — жёлтая заливка

**Статусы обучения по периодам:**
- Для программ 1–29 (кроме 5): статус «Обучен» если дата обучения в пределах 3 лет от текущей даты
- Если потребность есть, но дата отсутствует или результат «Неудовлетворительно» — статус «Не обучен»
- Если дата выходит за 3 года — статус «Просрочено»

**Запрос данных из реестра Минтруда по СНИЛС:**
- Кнопка «Запросить из реестра» — для всех сотрудников (с паузой 0.5 сек между запросами)
- Контекстное меню → «Запросить из реестра» — для одного сотрудника
- Брать последнюю успешную запись по дате по каждому номеру программы
- Если последняя запись «Неудовлетворительно» — статус «Не обучен»
- Полученные данные содержат: ФИО, СНИЛС, должность, номера программ, даты обучения, протоколы, результат, рег. номера

**Сводная аналитика:**
- Верхняя панель с карточками статистики:
  - Всего сотрудников (уникальных СНИЛС)
  - Всего записей (по всем программам)
  - Обучено / Не обучено / Просрочено
  - Актуальность данных (дата последнего общего запроса к реестру)

**Фильтрация и сортировка:**
- Фильтр по программе обучения (выпадающий список со всеми программами 1–29)
- Фильтр по статусу: «Все», «Обучен», «Не обучен», «Просрочено»
- Фильтр по должности (текстовый поиск)
- Быстрый фильтр «Только проблемные» — «Не обучен» + «Просрочено»
- Сортировка по всем столбцам
- Выбор отображаемых программ-колонок: кнопка «Выбрать программы» — диалог с чекбоксами (макс. 6), сохраняется в `data/summary_programs.json`

**Импорт/экспорт:**
- Кнопка «Импорт .xlsx» — загрузка данных (обязателен столбец СНИЛС)
- Кнопка «Экспорт .xlsx» — выгрузка текущего отображения (с учётом фильтров)
- Кнопка «Экспорт .xlsx (все)» — выгрузка всех данных без фильтров; пустая таблица → шаблон
- Формат: Фамилия, Имя, Отчество, СНИЛС, Должность, программа #1 … #29 (без #5) с подразделами

**Редактирование и удаление:**
- Контекстное меню → «Редактировать» — диалог изменения ФИО, СНИЛС, должности, списка программ
- Контекстное меню → «Удалить» — удаление выбранного сотрудника
- Кнопка «Удалить данные» (красная) — удаляет ВСЕ записи из сводки с подтверждением
- Двойной клик по колонке «Потребность» переключает Да/Нет

**Формирование планов обучения:**

**Кнопка «Сформировать план на текущий год»** — формирует список сотрудников для обучения/переобучения в текущем году.

Алгоритм для каждого сотрудника по каждой программе (если need_training = 1):
1. Нет даты обучения → включить, причина «Не обучен», срок = текущая дата + 60 дней, приоритет «Высокий»
2. Результат «Неудовлетворительно» → включить, причина «Не сдал», приоритет «Высокий»
3. Дата > 3 лет → включить, причина «Просрочено», приоритет «Средний»
4. Дата истекает в текущем году → включить, причина «Истекает в текущем году», приоритет «Низкий»

**Кнопка «Сформировать план на следующий год»** — аналогично, но для plan_year = current_year + 1.

Диалог перед формированием: чекбоксы (включать не обученных, просроченных, истекающих, не сдавших).

Результат — отдельное окно «План обучения на {год}» с карточками статистики и таблицей:
- №, ФИО, СНИЛС, Должность, Программа, Причина, Последняя дата обучения, Дата окончания, Приоритет

Кнопки: «Экспорт XLSX» (два листа: «План обучения» и «Сводка»), «Печать».

- `global_exception_handler` — перехват необработанных исключений

## 3. Структура данных

Все рабочие данные хранятся в `%APPDATA%/Excel_to_XML/`. Рядом с исполняемым файлом ничего не записывается.
SQLite-БД (`app_data.db`) — обычная (без файлового шифрования), персональные данные защищены полевым шифрованием.

```
%APPDATA%/Excel_to_XML/
 ├─ app_data.db              # SQLite (обычная БД, полное шифрование)
 ├─ app_data.db.backup.N     # Автоматические бэкапы (до 5 шт.)
 ├─ api_key.json             # Зашифрованный JSON — API ключ
 ├─ org_settings.json        # Зашифрованный JSON — настройки УЦ/Заказчика
 ├─ commission_data.json     # Зашифрованный JSON — данные комиссии
 ├─ proxy_settings.json      # Зашифрованный JSON — настройки прокси
 ├─ programs_data.json       # Зашифрованный JSON — номера документов и часы программ
 ├─ master.key               # Мастер-ключ (DPAPI или raw fallback)
 ├─ protocol_settings.json   # JSON — последний путь сохранения протокола
 ├─ journal_settings.json    # JSON — настройки журнала
 ├─ theme_settings.json      # JSON — выбранная тема
 ├─ summary_programs.json    # JSON — выбранные программы для сводки
 ├─ log/                     # Логи приложения
 │   ├─ app.log
```

### 3.5. Шифрование и безопасность

**Принцип:** SQLite-БД — обычная (без файлового шифрования). Персональные данные защищены на уровне отдельных полей (ФИО, СНИЛС). Конфиденциальные настройки шифруются целиком.

| Данные | Метод | Файл |
|--------|-------|------|
| SQLite-БД (ФИО, СНИЛС, программы, журнал) | Полевое шифрование (Fernet) | `app_data.db` |
| API-ключ Минтруда | Fernet | `api_key.json` |
| Настройки УЦ и Заказчика | Fernet | `org_settings.json` |
| Данные комиссии | Fernet | `commission_data.json` |
| Пароль прокси | Fernet | `proxy_settings.json` |
| Мастер-ключ | DPAPI (CryptProtectData) / raw fallback | `master.key` |

**Ключ шифрования (Мастер-ключ):**
- **Основной режим:** мастер-ключ генерируется случайно (32 байта) и защищается Windows DPAPI (привязка к учётной записи + машине)
- **Fallback:** если DPAPI недоступен, мастер-ключ сохраняется в открытом виде с предупреждением в логе

**Жизненный цикл БД:**
1. **Запуск**: SQLite открывается напрямую (WAL-журналирование)
2. **Работа**: чтение/запись зашифрованных полей через Fernet-ключ
3. **Поиск по СНИЛС**: через хеш-поле `snils_hash` (SHA256) — сам СНИЛС остаётся зашифрованным
4. **Бэкап**: копия `app_data.db` через shutil.copy2 — данные уже зашифрованы
5. **Закрытие**: обычное закрытие SQLite-соединения (повторного шифрования не требуется)

**Логирование:**
Все логи фильтруются через `SensitiveDataFilter`:
- СНИЛС: маскируются (`123-456-789 00` → `***-***-*** **`)
- Пароли: заменяются на `***`
- API-ключи: заменяются на `***`
- URL с credentials: заменяются на `https://***:***@***`

## 5. Нефункциональные требования

**Технологии:**
- Фронтенд: PySide6 (Qt for Python) — QWidgets, QTableWidget, QGroupBox, QScrollArea
- Бэкенд: Python 3.12+
- База данных: SQLite (единый файл `data/app_data.db`) + зашифрованные JSON для настроек
- Шифрование: cryptography (AES/Fernet) — полевое шифрование для SQLite (ФИО, СНИЛС), post-message для JSON-настроек
- Ключ: случайный 32-байтовый мастер-ключ, защищённый Windows DPAPI (с raw fallback)
- Логирование: SensitiveDataFilter (маскировка СНИЛС, паролей, ключей)

- XML: lxml (XSD-валидация), xml.etree.ElementTree
- Документы: python-docx (шаблоны DOCX)
- HTTP: requests (основной), WinINET (запасной, Windows API)
- Упаковка: PyInstaller (EXE)

**Стандарты кода:**
- Чистый код с комментариями
- Типизация (type hints)
- Централизованное логирование с фильтрацией чувствительных данных

**Производительность:**
- Фильтрация до 5000 записей: до 3 секунд
- Экспорт до 5000 записей: до 15 секунд
- Запрос к API Минтруда: зависит от скорости соединения (пагинация по 5000 записей)

**Ограничения:**
- Максимум 5000 записей в workers_data
- Максимум 300 записей на один протокол (DOCX)

## 6. Интеграция с API Минтруда

**Эндпоинты:**
- `POST https://edu.rosmintrud.ru/api/set/push` — отправка XML
- `POST https://edu.rosmintrud.ru/api/GetEducatedPersonXML` — запрос данных по SetId или СНИЛС

**Формат запроса (GetEducatedPersonXML):**
```xml
<EducatedPersonFilter>
    <ApiKey>32-символьный-ключ</ApiKey>
    <PageNo>1</PageNo>
    <PageSize>5000</PageSize>
    <Snils>СНИЛС-без-разделителей</Snils>
    <!-- или -->
    <SetId>идентификатор-набора</SetId>
</EducatedPersonFilter>
```

**Формат ответа:**
- `EducatedPersons` — список `RegistryRecord`, каждый содержит:
  - `Worker` (Snils, LastName, FirstName, MiddleName, Position, EmployerInn, EmployerTitle)
  - `Test` (learnProgramId, LearnProgramTitle, ProtocolNumber, Date, isPassed)
  - `baseNo` — регистрационный номер в реестре

## 7. Критерии приемки

1. Ручной ввод и загрузка из XLSX/XML работников с валидацией
2. Просмотр, редактирование и удаление записей
3. Конвертация данных в XSD-совместимый XML
4. Отправка XML в API Минтруда с получением SetId
5. Запрос регистрационных номеров по SetId и обновление журнала
6. Запрос данных из реестра по СНИЛС
7. Формирование протокола проверки знаний по шаблону DOCX
8. Отображение сводки по сотрудникам со статусами обучения
9. Импорт/экспорт .xlsx на вкладке «Сводка по сотрудникам»
10. Формирование планов обучения на текущий и следующий год
11. Шифрование конфиденциальных данных (AES/Fernet)
12. Автоматическое сохранение и загрузка состояния между сессиями
13. Фильтрация 5000 записей за ≤3 секунды, экспорт за ≤15 секунд
14. Сборка самодостаточного EXE через PyInstaller
