# Требования к системе Excel-XML для передачи данных в Минтруд.

## Назначение

Система предназначена для генерации XML файлов с данными работников, обученных требованиям охраны труда согласно 2464 в целях автоматизации внесения информации о работниках в базу данных Минтруда и генерации протоколов проверки знаний с целью оптимизации времени работы специалистов по охране труда.

## Глоссарий

- Система - разрабатываемое ПО

- Вкладка - отдельное окно программы

- Учебный центр - организация, проводящее обучение

- Заказчик -  организация, в которой числится работник (работодатель)

- XSD файл - схема создания XML документа, соответствующая требованиям Минтруда, с сайта https://akot.rosmintrud.ru/sout/info

- сайт Минтруда - https://lkot.mintrud.gov.ru/ , раздел Обучение по охране труда.

- Приоритеты: Must have (M) , Should have (S)  ,Could have (C)  , Won't have (W)

## Функциональные требования

### Загрузка данных (M)

1. **FR-001**: система должна поддерживать ручной ввод данных о работнике на вкладке "Внесение данных". (M)
   Описание: Пользователь заполняет форму работника вручную и сохраняет запись в системе.
   Обоснование: Позволяет завести запись без файлообмена.
   Критерии приемки:
   - AC-1: Есть поля для внесения данных: Фамилия, Имя, Отчество, Должность, СНИЛС, Номер программы, Номер протокола, Результат, Дата.
   - AC-2: При корректно заполненных полях запись создаётся, статус «Запись создана».
   - AC-3: При незаполненных обязательных полях система подсвечивает ошибки и не сохраняет.
   - AC-4: Валидация Фамилия, Имя, Отчество, Должность - только текст. При неправильном вводе - сообщение об ошибке ввода.
   - AC-5: Валидация СНИЛС - 11 цифр. Имеется возможность вставить данные из буфера обмена. При вводе вручную СНИЛС автоматически форматируется в вид "123-456-789 00" (расстановка "-" и " " при наборе цифр). При загрузке из Excel/XML СНИЛС также приводится к формату "123-456-789 00" независимо от исходного написания. При неправильном вводе - сообщение об ошибке после нажатия кнопки "Сохранить данные".
   - AC-6: Валидация Номер программы: числа от 1 до 29, за исключением 5. Знак ",".  Поддерживается запись в виде "1,2" и "1,2,". При неправильном вводе - сообщение об ошибке ввода после нажатия кнопки "Сохранить данные".
   - AC-7: Валидация Результат - только "Удовлетворительно" и "Неудовлетворительно". Формат поля - выпадающий список. По умолчанию выбрано "Удовлетворительно".
   - AC-8: при наличии в строке Номер программы более одной программы, разделенных запятыми, в систему вносится столько строк, сколько выбрано программ. Данные работника, УЦ, Работодателя повторяются во всех строках, уникальны номера программ. При дублировании - наличия строки с аналогичным СНИЛС и Номером программы - отображение ошибки с текстом "Выявлены аналогичные данные - х строк". Проверка дублей выполняется при ручном вводе и при импорте файлов.
   - AC-9: при нажатии кнопку "Сохранить данные" в разделе "Ручной ввод" данные строк вносятся в память программы и отображаются во вкладке "Просмотр данных". В случае отсутствия данных в строках появляется ошибка "Заполните все строки". После внесения данных все поля, кроме "№ программы", очищаются.
   - AC-10: при нажатии на кнопку "Очистить" в разделе "Ручной ввод" данные всех строк очищаются.
   - AC-11: валидация Дата - дата меньше или равна текущей даты, формат ввода в ячейку ЧЧ.ММ.ГГГГ или ЧЧММГГГГ. В случае ошибки ввода - сообщение "Дата некорректна. Ведите корректную дату в формате ЧЧ.ММ.ГГГГ или ЧЧММГГГГ". При загрузке из Excel поддерживаются даты в формате datetime и Excel serial date.
2. **FR-002**: система должна поддерживать ручной ввод данных об Учебном центре и Заказчике на вкладке "Внесение данных". (M)
   Описание: Пользователь вносит данные об учебном центре и работодателе вручную (ИНН и Название), и сохраняет запись в системе при нажатии на кнопку "Сохранить данные", расположенную под полями ввода.
   Обоснование: Позволяет внести обязательные данные для конвертации согласно схемы XSD.
   Критерии приемки:
   - AC-1: Имеются строки для внесения цифр : ИНН УЦ, ИНН Заказчика.
   - AC-2: имеются строки для ввода текста: Название УЦ, Название Заказчика.
   - AC-3: в строки возможно вставить данные из буфера обмена.
   - AC-4: внесенные данные сохраняются между сессиями.
   - AC-5: валидация ИНН - 10 или 12 цифр. В случае некорректного внесения - сообщение об ошибке "ИНН - только 10 или 12 цифр".
   - AC-6: в случае отсутствия данных в полях при нажатии кнопку "Сохранить данные" в разделе "Ручной ввод" появляется ошибка "Заполните данные УЦ/Работодателя".
   - При нажатии кнопки "Сохранить данные" введенная информация в полях сохраняется согласно  FR-009 
3. **FR-003**: система должна предоставлять данные об имеющихся программах обучения на вкладке "Внесение данных".(M)
   Описание: При нажатии на кнопку "Справка", расположенную возле строки "Номер программы" раздела ручного ввода, открывается перечень программ (№№1-26, без №5). При двойном клике на программу ее номер вносится в строку "Номер программы"
   Обоснование: Позволяет внести обязательные данные путем их выбора для удобства пользователя
   Критерии приемки:
   - AC-1: возле строки "Номер программы" раздела ручного ввода имеется кнопка "Справка", при нажатии на которую отображается перечень номероав и наименований программ обучения.
   - AC-2: при выборе программы двойным кликом ее номер вносится в строку "Номер программы" с автоматическим добавлением "," в конце.
   - AC-3: возможно выбрать от одной до десяти программ обучения. При большем количестве - уведомление "Превышено количество программ для одного работника".
4. **FR-004:** система должна поддерживать загрузку XLSX (xls) файлов с данными работников на вкладке "Внесение данных".(M)
   Описание: Пользователь выбирает XLSX(xls) , система валидирует и создаёт/обновляет записи в программе.
   Обоснование: Массовый импорт ускоряет первичное наполнение.
   Критерии приемки:
   - AC-1: Успешный импорт корректного файла создаёт записи согласно шаблону. Поддерживаются форматы .xlsx (openpyxl) и .xls (xlrd).
   - AC-2: Для строк с ошибками формируется отчёт и строки пропускаются. Формат отчета - информационное окно с текстом "Количество строк с ошибками: Х"
   - AC-3: Логирование ошибок импорта
   - AC-4: в случае успешного импорта - сообщение "Успешно загружено.
   - AC-5: в случае ошибки - сообщение "Ошибка импорта"
   - AC-6: поддерживаемый шаблон XLSX(xls) должен содержать следующие столбцы: Фамилия, Имя, Отчество, СНИЛС, Должность, ИНН Заказчика, Наименование ЮЛ Заказчика, ИНН УЦ, Наименование УЦ, Результат,№ программы, Дата, № протокола. Поля ИНН Заказчика, Наименование ЮЛ Заказчика, ИНН УЦ, Наименование УЦ являются необязательными. При отсутствии данных в этих полях подставляются значения, введённые на вкладке "Внесение данных" в разделе "Данные УЦ и работодателя".
5. **FR-005**: система должна поддерживать загрузку XML файлов с данными работников на вкладке "Внесение данных".(M)
   Описание: Импорт XML по XSD-схеме, валидация и создание/обновление записей.
   Обоснование: Массовый импорт ускоряет первичное наполнение.
   Критерии приемки:
   - AC-1: Файл, соответствующий XSD, импортируется без ошибок.
   - AC-2: При несоответствии XSD отображается список нарушений.
   - AC-3: Логирование ошибок импорта
   - AC-4: в случае успешного импорта - сообщение "Успешно загружено.
   - AC-5: в случае ошибки - сообщение "Ошибка импорта"
6. **FR-006**: система должна поддерживать загрузку XSD файла на вкладке "Внесение данных".(M)
   Описание: Импорт  XSD-схемы для валидации и создания/обновления записей.
   Обоснование: Создаваемые XML файлы должны соответствовать предоставляемой XSD, файл XSD может меняться
   Критерии приемки:
   - AC-1: Файл XSD импортируется без ошибок.
   - AC-2: загружаемые XML файлы валидируются по загруженному XSD
   - AC-3: Логгирование ошибок импорта
   - AC-4: загруженная схема XSD сохраняется в файлах приложения.    
   - AC-5: в случае успешного импорта - сообщение "Успешно загружено.
   - AC-6: в случае ошибки - сообщение "Ошибка импорта"
   - AC-7: сохраненная схема размещается в подразделе "schema" корневой директории программы.
7. **FR-007**: система должна направлять на сайт Минтруда с актуальной схемой XSD. (M)
   Описание: при нажатии на кнопку "Схема XSD" система открывает браузер со ссылкой "https://akot.rosmintrud.ru/sout/info"
   Обоснование: при необходимости обновления схемы XSD в случае ее изменения.
   Критерии приемки:

- AC-1: при нажатии на кнопку "Схема XSD" открывается браузер со ссылкой "https://akot.rosmintrud.ru/sout/info"

8. **FR-008**: система должна формировать шаблон xlsx файла для заполнения. (M)
   Описание: при нажатии на кнопку "Создать шаблон" система генерирует xlsx файл в корневом хранилище приложения.
   Обоснование: формирование шаблона, поддерживаемого программой
   Критерии приемки:

- AC-1: при нажатии на кнопку "Создать шаблон" система генерирует xlsx файл с именем "Шаблон.xlsx" со столбцами: Фамилия, Имя, Отчество, СНИЛС, Должность, ИНН Заказчика, Наименование ЮЛ Заказчика, ИНН УЦ, Наименование УЦ, Результат,№ программы, Дата, № протокола.
- AC-2: после создания файла система уведомляет пользователя окном уведомления "Шаблон создан. Открыть расположение файла?". В случае нажатия кнопки Открыть - открывается расположение файла (корневая папка программы), в случае нажатия кнопки Отмена - диалоговое окно закрывается.



## FR-009: Сохранение данных УЦ и Заказчика в JSON

**Описание**: Данные об Учебном центре и Заказчике должны сохраняться между сессиями в файле формата JSON, расположенном в директории `/data/` приложения, вместо использования системного реестра или QSettings.

**Обоснование**:

- Переносимость настроек между разными системами
- Возможность ручного редактирования конфигурации
- Прозрачность хранения данных
- Упрощение резервного копирования и миграции

**Критерии приемки**:

- AC-1: При запуске приложения данные об УЦ и Заказчике загружаются из файла `/data/org_settings.json`
- AC-2: При нажатии кнопки "Сохранить данные" информация об УЦ и Заказчике сохраняется в файл `/data/org_settings.json`
- AC-3: Файл имеет формат JSON с полями: `tc_inn`, `tc_title`, `employer_inn`, `employer_title`
- AC-4: При отсутствии файла создается новый с пустыми значениями
- AC-5: При ошибке чтения/записи файла пользователю отображается предупреждение

**Пример структуры JSON**:

```json
{
    "tc_inn": "1234567890",
    "tc_title": "Учебный центр \"Профессионал\"",
    "employer_inn": "0987654321",
    "employer_title": "ООО \"Работодатель\""
}
```

### Отображение данных (M)

9. **FR-010**: система должна формировать на вкладке "Просмотр данных" перечень работников согласно внесенных данных из нескольких файлов различного типа и вручную. (M)
   Описание: создание перечня данных для конвертирования, полученных из разных источников
   Обоснование: возможность формирования данных из перечней данных.
   Критерии  приемки:
   - AC-1: в систему загружаются данные из файлов xlsx, xml, данные отображаются корректно
   - AC-2: при загрузке второго и далее файлов появляется диалоговое окно "что делать с данными" с кнопками "объединить, удалить старые, отменить загрузку". При нажатии "объединить" - новые данные добавляются к имеющимся, "удалить старые" - остаются только вновь добавленные данные, "отмена" - остаются имеющиеся данные.
   - AC-3: при объединении данных добавляются строки работников с уникальными СНИЛС и номерами программ. Дубликаты (совпадение пары СНИЛС + № программы) пропускаются. Приоритет имеют уже существующие в системе данные.

### Передача данных в Минтруд (M)

14. **FR-019**: Система должна поддерживать ввод и сохранение API ключа для сайта Минтруда (M)

15. **FR-020**: Система должна направлять сгенерированный XML файл на сервер Минтруда (M)
      Описание: отправка XML файла с данными обученных работников на сервер Минтруда
      Обоснование: выполнение операции из программы, минуя интерфейс сайта Минтруда
      Критерии  приемки:

   - AC-1: Имеется раздел "Отправка XML" на вкладке "Передача данных". В разделе имеется поле для выбора файла "XML файл" с кнопкой "Выбрать". При нажатии на кнопку открывается окно выбора XML файла. После выбора файл валидируется согласно XSD. При несоответствии - сообщение "Файл не соответствует схеме".
   - AC-2: при нажатии кнопки "Отправить XML на сервер" система повторно валидирует API ключ и направляет файл согласно алгоритму BR-2. Отправка: POST на https://edu.rosmintrud.ru/api/set/push, Content-Type: multipart/form-data. Запрос содержит два файла: Request.xml (ApiKey + NeedSend=false) и Data.olot (ZIP-архив с Data.xml внутри, название с заглавной D).

   - AC-4: при ошибке полный ответ сервера сохраняется в файл /log/error_response.txt в кодировке UTF-8 BOM для корректного отображения кириллицы.

      Обоснование: Пользователь теряет SetId после закрытия диалога. Журнал позволяет отслеживать историю отправок, связывать SetId с конкретными работниками и автоматически подтягивать регистрационные номера.
      Критерии  приемки:
   - AC-1: При успешной отправке XML на сервер (получен SetId) система автоматически создаёт записи в журнале для каждого работника из отправленного файла. Каждая запись содержит: Фамилия, Имя, Отчество, СНИЛС, Должность, Номер программы, Название программы, Дата, Номер протокола, SetId, baseNo (пусто на момент отправки), send_date (дата/время отправки), xml_file_path.
   - AC-2: Данные журнала сохраняются в файл `/data/exam_journal.json` в кодировке UTF-8.
   - AC-3: При повторном запуске приложения журнал загружается из файла и доступен для просмотра.
   - AC-4: При ошибке отправки XML записи в журнал НЕ создаются.

13. **FR-018**: система должна конвертировать данные в формат XML в соответствии с приложенным XSD файлом. (M)
      Описание: При нажатии кнопки "Конвертация" на вкладке "Просмотр данных"  система должна конвертировать имеющиеся данные в формат XML в соответствии с загруженным XSD файлом.
      Обоснование: сайтом Минтруда поддерживается загрузка XML файла, соответствующего XSD схеме.
      Критерии  приемки:

   - AC-1: при нажатии кнопки кнопки "Конвертация" на вкладке  "Просмотр данных" предлагается выбрать место размещения и имя создаваемого файла
   - AC-2: при нажатии кнопки проводится конвертация данных в соответствие со схемой XSD, размещенной в папке "schema". Формат XML: корневой элемент RegistrySet, каждый RegistryRecord (maxOccurs=5000) содержит Worker, Organization (УЦ), Test (с атрибутами isPassed, learnProgramId). Группировка по протоколу НЕ выполняется — каждая запись отдельна. Дата в формате xs:date (YYYY-MM-DD). isPassed = "true" для "Удовлетворительно", "false" для "Неудовлетворительно".
   - AC-3: созданный файл принимается информационной системой Минтруда (при ручной загрузке)
   - AC-4: в случае отсутствия загруженного XSD файла при нажатии кнопки появляется уведомление "XSD отсутствует"
   - AC-5: XML Должен формироваться в формате UTF-8
   - AC-6: в XML СНИЛС сохранен в виде "123-456-789 00" для отображения в программе, при отправке на сервер СНИЛС передается в этом же формате
   - AC-7: при отправке на сервер Минтруда формируется multipart/form-data запрос с двумя файлами: Request.xml (содержит ApiKey и NeedSend=false) и Data.olot (ZIP-архив с файлом Data.xml внутри, название с заглавной D). Отправка POST-методом на https://edu.rosmintrud.ru/api/set/push
