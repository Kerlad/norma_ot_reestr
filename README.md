## 📋 Описание

Система для генерации XML-файлов с данными работников, обученных требованиям охраны труда (постановление №2464), и отправки данных в информационную систему Минтруда России через API.

### Ключевые особенности

- 📝 **Ручной ввод данных** — внесение информации о работниках через удобную форму
- 📊 **Загрузка из Excel/XML** — массовый импорт данных из файлов `.xlsx`, `.xls`, `.xml`
- ✅ **Валидация по XSD** — проверка соответствия схеме Минтруда
- 🚀 **Отправка на сервер** — загрузка XML напрямую на edu.rosmintrud.ru
- 🔍 **Получение рег. номеров** — запрос регистрационных номеров по SetId или СНИЛС
- 📓 **Журнал проверки знаний** — история всех отправок с отслеживанием статусов
- 📄 **Формирование протокола** — автоматическое заполнение шаблона протокола проверки знаний
- 📄 **Протокол одиночного работника** — создание протокола без использования данных журнала
- 🔐 **Безопасное хранение** — полевое шифрование персональных данных (ФИО, СНИЛС) + шифрование API-ключа и настроек прокси (Fernet + Windows DPAPI key protection)
- 🎨 **Современный UI** — интерфейс на PySide6 с интуитивной навигацией и темами
- 🌐 **WinINET** — встроенный HTTP-транспорт Windows с поддержкой системных прокси и NTLM/Negotiate

## 🚀 Возможности

### Внесение данных
- Ввод данных учебного центра и заказчика (ИНН, название) с выравниванием полей
- Ручное внесение данных работников с валидацией полей
- Автоформатирование СНИЛС в вид `123-456-789 00`
- Поддержка множественных программ обучения (1–29, кроме 5)
- Создание шаблона XLSX для заполнения

### Просмотр данных
- Таблицы с данными всех работников с многострочными заголовками
- Объединение или замена данных при загрузке новых файлов
- Редактирование и удаление записей через контекстное меню
- Конвертация в XML по схеме XSD

### Передача данных
- Ввод и сохранение API-ключа (32 символа)
- Настройки прокси: без прокси / авто (системные) / вручную
- **Transport backend selection** — выбор HTTP-транспорта (Auto/Requests/WinINET)
- **WinINET** — встроенный Windows HTTP-транспорт (системные прокси, NTLM/Negotiate)
- Отправка XML на сервер Минтруда
- Получение SetId после успешной загрузки
- Запрос регистрационных номеров по SetId или СНИЛС
- Экспорт результатов в XLSX

### Журнал проверки знаний
- Автоматическое сохранение истории отправок
- Цветовая индикация статусов: «ожидает» / «получен»
- Поиск и фильтрация по ФИО/СНИЛС, SetId, статусу, номеру протокола, диапазону дат
- Автоматическое обновление регистрационных номеров по SetId
- Экспорт отфильтрованных записей в XLSX
- Печать протокола по данным журнала (один или все протоколы)

### Формирование протокола
- Заполнение шаблона `Protokol_proverki_znanii_OT.docx`
- Выбор номера протокола из списка или "Все"
- Автозаполнение даты проверки знаний из журнала
- Данные комиссии: название организации, приказ, председатель, члены комиссии, профсоюз
- Данные сохраняются между сессиями
- Группировка по ФИО (одна строка для совпадающих)
- Объём проверки знаний из программ обучения с номерами документов и часами
- Именование файлов: «Протокол {номер} от {дата}.docx»
- При выборе «Все» — каждый протокол сохраняется в отдельный файл

### Протокол одиночного работника
- Создание протокола без использования данных журнала
- Все поля вводятся вручную: ФИО, должность, программы, дата, номер протокола
- Все поля необязательные (пустые поля = пустые в протоколе)
- Поддержка нескольких программ обучения (через запятую)
- Кнопка "Справка" для выбора программ из списка

### Сводка по сотрудникам
- Справочник сотрудников с ручным вводом и импортом из XLSX
- Динамические колонки программ обучения (по умолч. 1,2,3,4,18,23)
- Цветовая индикация статусов: обучен (зелёный), не обучен (красный), просрочено (жёлтый)
- Карточки статистики: всего сотрудников, обучено/не обучено/просрочено
- Запрос истории обучения из реестра Минтруда по СНИЛС (с таймаутом между запросами)
- Автоматическое формирование плана обучения на текущий/следующий год
- Сводка по приоритетам: высокий / средний / низкий
- Экспорт XLSX с фильтрацией

## 🔐 Архитектура безопасности

### Модель хранения данных

| Компонент | Место | Формат |
|-----------|-------|--------|
| База данных | `%APPDATA%/Excel_to_XML/app_data.db` | SQLite (WAL) |
| Персональные данные (ФИО, СНИЛС) | В БД | Полевое шифрование (Fernet) |
| API-ключ | `%APPDATA%/Excel_to_XML/api_key.json` | Encrypted (Fernet) |
| Прокси-учётные данные | `%APPDATA%/Excel_to_XML/proxy_settings.json` | Encrypted (Fernet) |
| Мастер-ключ | `%APPDATA%/Excel_to_XML/master.key` | Зашифрован через DPAPI (Windows) |
| Логи | `%APPDATA%/Excel_to_XML/log/` | Plain text с SensitiveDataFilter |
| Резервные копии БД | `%APPDATA%/Excel_to_XML/backups/` | С сохранением шифрования |

### Полевое шифрование (Fernet)

Персональные данные (ФИО, СНИЛС) шифруются **на уровне отдельных полей** перед записью в SQLite.
Поиск по СНИЛС работает через хешированное поле `snails_hash` — сам СНИЛС в БД хранится только в зашифрованном виде.
Благодаря полевому шифрованию резервные копии БД не требуют отдельного шифрования — данные уже зашифрованы.

### DPAPI Master Key

Мастер-ключ для Fernet защищается **Windows DPAPI** (CryptProtectData):
- Привязка к **учётной записи Windows** и **конкретной машине**
- Другой пользователь на том же ПК не сможет расшифровать данные
- При переустановке системы мастер-ключ теряется (требуется restore из резервной копии)

### Fallback режим

Если DPAPI недоступен (Windows 7/8 без профиля, терминальные сессии без ройминга), мастер-ключ сохраняется **в открытом виде** в `%APPDATA%/Excel_to_XML/master.key`.
В лог выводится предупреждение: `DPAPI unavailable, using local fallback key (reduced security)`.
Это сознательное решение: данные всё ещё защищены полем шифрованием на уровне файловой системы, но без DPAPI мастер-ключ не привязан к учётной записи.

### Фильтрация логов

Все логи (app.log, error.log, audit.log) проходят через `SensitiveDataFilter`, который автоматически маскирует:
- СНИЛС (`123-456-789 00` → `***-***-*** **`)
- Пароли, API-ключи, токены
- ФИО (полные русские имена)
- URL с встроенными учётными данными
- Прокси-адреса

### Безопасность сети

- **TLS verify=True** по умолчанию (отключается только явно через настройки)
- Автоматический fallback между транспортами **requests** и **WinINET** при SSL-ошибках
- Поддержка корпоративных прокси с аутентификацией (`http://user:pass@host:port`)
- **Windows Integrated Authentication** (Negotiate/Kerberos) для корпоративных прокси
- Retry-политика: 3 попытки с экспоненциальной задержкой (429, 500, 502, 503, 504)

## 💻 Использование

### Запуск приложения

```bash
python main.py
```

### Пошаговая инструкция

#### 1. Начальная настройка
1. Откройте вкладку **«Внесение данных»**
2. Заполните раздел **«Данные УЦ и работодателя»**:
   - ИНН УЦ (10 или 12 цифр)
   - Название УЦ
   - ИНН Заказчика (10 или 12 цифр)
   - Название Заказчика
3. Нажмите **«Сохранить данные»**

#### 2. Загрузка данных

**Вариант А: Ручной ввод**
1. Заполните форму работника:
   - ФИО, должность, СНИЛС
   - Номер программы (1–29, кроме 5)
   - Номер протокола, результат, дата
2. Нажмите **«Сохранить данные»**

**Вариант Б: Импорт из файла**
1. В разделе **«Загрузка данных»** нажмите **«Выбрать файл»**
2. Выберите `.xlsx`, `.xls` или `.xml` файл
3. Нажмите **«Загрузить файл»**

#### 3. Конвертация в XML
1. Перейдите на вкладку **«Просмотр данных»**
2. Проверьте загруженные записи
3. Нажмите **«Конвертировать»**
4. Выберите путь для сохранения XML-файла

#### 4. Отправка в Минтруд
1. Перейдите на вкладку **«Передача данных»**
2. Введите API-ключ (32 символа) из личного кабинета на edu.rosmintrud.ru
3. Нажмите **«Сохранить ключ»**
4. При необходимости настройте прокси и выберите Transport backend
5. В разделе **«Отправка XML»** выберите XML-файл
6. Нажмите **«Отправить XML на сервер»**
7. **Запишите полученный SetId** — он нужен для запроса рег. номеров

#### 5. Получение регистрационных номеров
1. В разделе **«Запрос по SetId»** введите полученный SetId
2. Нажмите **«Запросить номера»**
3. Сохраните XLSX-файл с регистрационными номерами

#### 6. Формирование протокола
1. Перейдите на вкладку **«Протокол»**
2. Заполните данные комиссии: название организации, № протокола, дата проверки, приказ, состав комиссии
3. Нажмите **«Сохранить данные комиссии»**
4. Выберите номер протокола из списка (или «Все» для генерации всех протоколов)
5. Нажмите **«Сгенерировать протокол»**

**Имена файлов:**
- Одиночный протокол: «Протокол {номер} от {дата}.docx»
- При выборе «Все» — каждый протокол сохраняется в отдельный файл в выбранную папку

> ⚠️ **Важно:** После загрузки данных на сервер необходимо перейти на сайт edu.rosmintrud.ru, открыть загруженный реестр, указать структурное подразделение и подписать документы УКЭП. Без подписи данные не будут переданы в реестр.

## 🔐 API Минтруда

### Настройка API-ключа

1. Зарегистрируйтесь на [edu.rosmintrud.ru](https://edu.rosmintrud.ru)
2. Перейдите в личный кабинет
3. Сгенерируйте API-ключ (32 символа)
4. Вставьте ключ в приложение на вкладке **«Передача данных»**

### Transport Backends

Приложение поддерживает несколько HTTP-транспортов для отправки запросов:

| Backend | Описание | Преимущества |
|---------|----------|--------------|
| Auto | Автоматический выбор лучшего | Fallback между requests и WinINET |
| Requests | Библиотека requests | Windows Integrated Authentication (Negotiate/Kerberos) |
| WinINET | Windows Internet API | Лучшая поддержка корпоративных прокси |

### Безопасность

#### Модель шифрования

Приложение использует **двухуровневую модель защиты персональных данных**:

1. **Полевое шифрование** (AES/Fernet) — чувствительные поля (ФИО, СНИЛС) шифруются по отдельности перед записью в SQLite (`encrypt_value`/`decrypt_value`)
2. **Шифрование настроек** (AES/Fernet) — API-ключ, данные УЦ, комиссии, пароль прокси шифруются в JSON-файлах (`encrypt_data`/`decrypt_data`)
3. **Поисковые хеши** (SHA256) — для поиска по СНИЛС используется хеш, поиск по зашифрованным полям не производится

#### Ключ шифрования

- **Основной:** DPAPI (`CryptProtectData`) + 32-байтовый случайный ключ (`os.urandom(32)`) в `%APPDATA%/Excel_to_XML/master.key`
- **Резервный (без DPAPI):** ключ сохраняется напрямую в `master.key`
- Ключ привязан к учётной записи Windows

| Что шифруется | Метод | Хранение |
|---------------|-------|----------|
| ФИО, СНИЛС (БД) | Полевое AES/Fernet | SQLite (`_enc` поля) |
| API-ключ Минтруда | AES/Fernet | `%APPDATA%/Excel_to_XML/api_key.json` |
| Настройки УЦ и Заказчика | AES/Fernet | `%APPDATA%/Excel_to_XML/org_settings.json` |
| Данные комиссии | AES/Fernet | `%APPDATA%/Excel_to_XML/commission_data.json` |
| Пароль прокси | AES/Fernet | `%APPDATA%/Excel_to_XML/proxy_settings.json` |

#### Хранение данных

Все данные приложения хранятся в `%APPDATA%/Excel_to_XML/`:

```
%APPDATA%/Excel_to_XML/
 ├── app_data.db                # SQLite (полевое шифрование)
 ├── master.key                 # Ключ шифрования (DPAPI или raw)
 ├── backups/                   # Бэкапы БД (ротация 5 шт.)
 ├── log/                       # Логи приложения
 │   ├── app.log               # Основной лог (INFO+)
 │   ├── error.log             # Только ошибки (ERROR+)
 │   └── audit.log             # Аудит действий
 ├── settings/                  # Настройки (зашифрованные)
 │   ├── api_key.json
 │   ├── org_settings.json
 │   ├── commission_data.json
 │   └── proxy_settings.json
 └── *.json                     # UI-настройки
```

#### Логирование

**Маскировка чувствительных данных** — все логи проходят через `SensitiveDataFilter`:
- СНИЛС → `***-***-*** **` или `***********`
- Пароли → `***`
- API-ключи → `***`
- URL с credentials → `https://***:***@***`

**Уровень логирования:** INFO (продакшн) / DEBUG (режим отладки)

**Аудит-лог** — отдельный файл `audit.log` для ключевых действий:
- Отправка XML (SEND_XML)
- Запрос реестра (QUERY_SETID, QUERY_SNILS)
- Импорт данных (IMPORT_XLSX, IMPORT_XML)
- Экспорт (EXPORT_XML, EXPORT_XLSX)
- Бэкапы (BACKUP)

### Корпоративные прокси

- **Автоопределение:** автоматически читает настройки прокси из реестра Windows
- **Ручная настройка:** поддерживает Basic-аутентификацию через `http://user:pass@host:port`
- **WPAD:** поддерживается через системные настройки
- **TLS:** включён по умолчанию, отключается через UI для корпоративных SSL-инспекций

### Эндпоинты API

| Endpoint | Метод | Назначение |
|----------|-------|------------|
| `https://edu.rosmintrud.ru/api/set/push` | POST | Отправка XML на сервер |
| `https://edu.rosmintrud.ru/api/GetEducatedPersonXML` | POST | Запрос рег. номеров |

## 📄 Протокол проверки знаний

### Структура протокола

Шаблон `Protokol_proverki_znanii_OT.xlsx` заполняется автоматически:

| Ячейка | Содержание |
|--------|------------|
| F2 | Номер протокола |
| B5 | Название организации |
| G7 | Дата проверки знаний |
| B9 | Приказ (номер + дата) |
| D12–D16 | ФИО председателя и членов комиссии |
| D18 | ФИО представителя профсоюза |
| B20–B24 | Объём проверки знаний (программы) |
| D30, D32–D34, D37 | Подписи членов комиссии |
| Строка 28+ | Таблица работников |

### Объём проверки знаний

Текст программы формируется автоматически:
```
Название программы, Номер документа, в объеме X часов
```

Данные берутся из окна «Программы обучения» (кнопка на вкладке «Протокол»), где для каждой программы можно указать номер документа и количество часов.

## 🛠 Разработка

### Добавление новых функций

1. Создайте новую ветку:
   ```bash
   git checkout -b feature/new-feature
   ```

2. Внесите изменения и запустите проверку:
   ```bash
   python -m py_compile main.py
   ```

3. Зафиксируйте изменения:
   ```bash
   git add .
   git commit -m "Добавлена функциональность: описание"
   ```

### Создание исполняемого файла

**Вариант 1: PyInstaller (рекомендуется)**
```bash
pip install pyinstaller
pyinstaller ExcelXML.spec
```
Результат: `dist/ExcelXML-Mintrud/ExcelXML-Mintrud.exe` (около 6 МБ + библиотеки)

**Вариант 2: C# лаунчер + исходники**
```bash
csc Launcher.cs
```
Результат: `Launcher.exe` (~5 КБ) — запускает `python main.py`, не требует упаковки

**Параметры сборки:**
- `onedir` — директория с библиотеками (не UPX, чтобы избежать ложных срабатываний АВ)
- `--noconsole` — без консольного окна
- `--icon=ico.ico` — иконка приложения
- `--version=version_info.txt` — версия

### Логирование

Логи хранятся в `%APPDATA%/Excel_to_XML/log/`:

| Файл | Назначение | Уровень |
|------|------------|---------|
| `app.log` | Основной лог приложения | INFO+ (ротация 5×5МБ) |
| `error.log` | Только ошибки | ERROR+ |
| `audit.log` | Аудит действий | INFO (отдельный файл) |

Логи автоматически фильтруют СНИЛС, пароли, API-ключи (`SensitiveDataFilter`).

### Поиск и устранение неисправностей

| Проблема | Решение |
|----------|---------|
| Не отправляется XML | Проверьте API-ключ (32 символа), настройки прокси, TLS-сертификат |
| Ошибка прокси | Включите «Авто (системные)» или настройте вручную `http://user:pass@host:port` |
| SSL-ошибки | Отключите «Проверять TLS» в настройках прокси (для корпоративных SSL-инспекций) |
| Не загружается Excel | Проверьте заголовки колонок: Фамилия, Имя, СНИЛС, Дата и т.д. |
| Не конвертируется XML | Убедитесь, что XSD-схема есть в папке `schema/` |
| Где логи? | `%APPDATA%/Excel_to_XML/log/` |
| Где БД? | `%APPDATA%/Excel_to_XML/app_data.db` |
| Сброс настроек | Удалите `%APPDATA%/Excel_to_XML/` (кроме master.key!) |
