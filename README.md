## 📋 Описание

Десктопное приложение для Windows, которое закрывает полный цикл работы специалиста по охране труда с реестром Минтруда:

**внесение данных → XML по схеме Минтруда → отправка в реестр (`edu.rosmintrud.ru`) → регистрационные номера → протоколы проверки знаний → сводка и план обучения.**

- Все данные хранятся **только на вашем компьютере** (`%APPDATA%\NormaOT`), ФИО и СНИЛС шифруются. Телеметрии нет, сеть используется только для обмена с реестром.
- Срок повторного обучения — **3 года для всех программ** (1–4 и 6–29), как в редакции ПП № 2464 с 01.09.2026.
- Весь функционал бесплатный, исходный код открыт (MIT).

## 🚀 Возможности

### Вкладки программы

| Вкладка | Что делает |
|---|---|
| **Внесение данных** | Ручной ввод (СНИЛС форматируется как `XXX-XXX-XXX XX`), импорт `.xlsx` (до 10 МБ / 100 000 строк) и `.xml` (с проверкой по XSD), шаблон XLSX, данные учебного центра и заказчика |
| **Просмотр данных** | Таблица записей, редактирование и удаление, «Заполнить УЦ и Заказчика», конвертация в XML по схеме Минтруда |
| **Передача данных** | Отправка XML в реестр, в том числе с электронной подписью `.sig` (архив `.olot` для РОЛ); запрос регистрационных номеров по SetId или СНИЛС; настройки прокси |
| **Журнал проверки знаний** | История отправок с цветными статусами, фильтры, автообновление рег. номеров, «Запросить по…» (SetId / СНИЛС), импорт файла-ответа по SetId без дублей |
| **Настройка протоколов** | Состав комиссии, программы обучения, данные организации, шаблон DOCX |
| **Быстрый протокол** | Протокол проверки знаний на одного работника с ручным вводом |
| **Сводка по сотрудникам** | Справочник работников и их программ, статусы «Не обучен / Просрочено / Обучен», запрос из реестра по СНИЛС, «Импорт отчёта из реестра», план обучения, отчёт по обученным, «Текущая ситуация», импорт/экспорт XLSX |

### Несколько организаций

- Меню **«Организация»**: добавить, выбрать при запуске, переключить, удалить.
- У каждой организации свои сотрудники, журнал, API-ключ и настройки протоколов; мастер-ключ, логи и тема общие.

### Работа в корпоративной сети

- Транспорт WinHTTP (единые с Windows прокси и Kerberos/NTLM), запасные транспорты `urllib` и `requests` — при ошибке TLS программа сама пробует следующий.
- Автоопределение корпоративной среды (например, прокси РЖД), ручная настройка прокси.
- При SSL-инспекции прокси программа предлагает повторить отправку без проверки сертификата — только с подтверждением пользователя и записью в журнал аудита.

### Удобство

- Темы: светлая, тёмная, Dracula, Monokai.
- Ширина столбцов таблиц запоминается, размер и положение окна тоже.
- Справка по работе с программой — `F1`, справочник номеров программ обучения — в меню «Справка».

## 🩺 Решение проблем

### «Ошибка поддержки безопасных каналов» / ошибка TLS при отправке или запросе

Windows не смогла установить защищённое соединение с `edu.rosmintrud.ru` (WinHTTP 12157). Чаще всего встречается на Windows 10.

1. **Обновите программу до 3.8.1 или новее.** Начиная с этой версии программа явно включает TLS 1.2/1.3, а при неудаче сама повторяет запрос через встроенный OpenSSL-транспорт.
2. Установите обновления Windows (старые сборки Windows 10 не поддерживают наборы шифров, которые требует сервер).
3. Проверьте дату и время на компьютере — при неверных часах сертификат сервера считается недействительным.
4. Если ошибка говорит о недоверенном центре сертификации, а в организации есть прокси с SSL-инспекцией — обратитесь в ИТ-службу или повторите отправку без проверки сертификата (программа предложит это сама; флажок «Проверять TLS-сертификат сервера» на вкладке «Передача данных»).

### Windows предупреждает о неизвестном издателе

Это ожидаемо для самоподписанного сертификата: нажмите «Подробнее → Выполнить в любом случае». Проверить подлинность файла можно по SHA-256 архива и отпечатку сертификата (см. [Скачать](#-скачать)). Для организаций — [docs/CODE_SIGNING.md](docs/CODE_SIGNING.md).

### Где лежат данные и логи

- Данные: `%APPDATA%\NormaOT` (до версии 3.6.0 — `%APPDATA%\Excel_to_XML`, переносятся автоматически).
- Логи: `%APPDATA%\NormaOT\log`, просмотр — «Инструменты → Просмотр логов». Полный ответ сервера при ошибке сохраняется в `log\error_response.txt`.
- Полное удаление — «Инструменты → Удалить все данные приложения».

Если проблема не решилась — напишите на [denis.krv@yandex.ru](mailto:denis.krv@yandex.ru) (кнопка «Сообщить об ошибке» — в меню «Настройки → Безопасность»). Не присылайте файлы с реальными СНИЛС и ФИО.

## 🔐 Защита персональных данных

Программа обрабатывает ПДн работников (ФИО, СНИЛС) и рассчитана на ИСПДн УЗ-3.

| Уровень | Технология |
|---------|-----------|
| Хранение | Только локально, `%APPDATA%\NormaOT`; ФИО и СНИЛС шифруются по полям (Fernet, AES-128-CBC + HMAC) |
| Мастер-ключ | Windows DPAPI (привязан к пользователю Windows) + необязательная парольная фраза (PBKDF2-HMAC-SHA256, 600 000 итераций) |
| Сеть | Только `edu.rosmintrud.ru`, TLS 1.2+, проверка сертификата по умолчанию |
| XML | Безопасный разбор (defusedxml, лимиты на размер и глубину), проверка по XSD |
| Логи | Фильтр ПДн и секретов (СНИЛС, ФИО, телефоны, ключи, токены) |
| Аудит | Журнал событий безопасности с HMAC-цепочкой, проверка целостности в «Инструменты → Просмотр логов» |
| Сессия | Автоблокировка по таймауту, `Ctrl+L` |
| Временные файлы | Изолированный каталог с доступом только для пользователя, затирание при удалении |

Если парольная фраза потеряна, зашифрованные данные восстановить нельзя.

Подробно: [docs/SECURITY.md](docs/SECURITY.md) · [docs/HARDENING.md](docs/HARDENING.md) · [docs/OPSEC_GUIDE.md](docs/OPSEC_GUIDE.md) · [docs/PRIVACY.md](docs/PRIVACY.md) · [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md)

### ⚠️ Ограничения

- Программа **не** является сертифицированным СКЗИ, сертификация ФСТЭК/ФСБ не проводилась, ГОСТ-криптография не используется.
- Защищённость данных зависит от защищённости рабочего места (BitLocker, антивирус, обновления, учётные записи).
- Организационные меры (политика обработки ПДн, приказы, допуск) обязательны и техническими средствами программы не заменяются.

## 🛠 Разработка

### Запуск из исходников

Требования: Windows 10/11, Python 3.12.

```bash
git clone https://github.com/Kerlad/Excel_to_XML.git
cd Excel_to_XML
py -m pip install -r requirements.txt
py main.py
```

### Тесты

```bash
py -m pytest tests -q
```

Тесты используют только вымышленные СНИЛС и ФИО и не трогают реальную папку данных (`tests/conftest.py` подменяет `APPDATA`).

### Сборка EXE

```bash
py -m PyInstaller NormaOT_Reestr.spec --noconfirm
```

Сборка в папку `dist/NormaOT_Reestr/` (`schema/`, `templates/`, `resources/` — в `_internal/`), версия EXE берётся из `VERSION` в `utils/about_dialog.py`. Подпись — `tools/sign_build.ps1` (до упаковки в zip), полный порядок выпуска — в [AGENTS.md](AGENTS.md#exe-build--release).

### Структура проекта

```
Excel_to_XML/
├── main.py              # Точка входа, главное окно, меню
├── tabs/                # Вкладки и диалоги (PySide6)
├── api/                 # Клиент реестра Минтруда
│   └── backends/        # Транспорты: WinHTTP, urllib, requests
├── db/                  # SQLite (DatabaseManager), репозитории
├── importers/           # Импорт XLSX / XML
├── exporters/           # Генерация XML / XLSX / DOCX
├── journal/             # Журнал отправок, синхронизация с реестром
├── protocol/            # Комиссия, программы обучения
├── network/             # Диагностика сети
├── utils/               # Шифрование, аудит, логи, организации, лицензия, UI
├── schema/              # XSD-схемы Минтруда
├── templates/           # Шаблоны DOCX/XLSX
├── tools/               # Подпись сборки, служебные скрипты
├── tests/               # Автотесты (pytest)
├── docs/                # Документация
└── Reports/             # Отчёты аудита и соответствия
```
