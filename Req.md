## Назначение

Система предназначена для генерации XML файлов с данными работников, обученных требованиям охраны труда согласно 2464 в целях автоматизации внесения информации о работниках в базу данных Минтруда и генерации протоколов проверки знаний с целью оптимизации времени работы специалистов по охране труда.

## Глоссарий

- Система - разрабатываемое ПО
- Go - язык программирования (https://go.dev)
- Wails - фреймворк для GUI на Go (https://wails.io)
- excelize - библиотека Go для работы с XLSX
- Учебный центр - организация, проводящее обучение
- Заказчик - организация, в которой числится работник (работодатель)
- XSD файл - схема создания XML документа, соответствующая требованиям Минтруда
- сайт Минтруда - https://edu.rosmintrud.ru
- SetId - уникальный идентификатор загрузки данных в систему Минтруда
- Регистрационный номер - уникальный номер записи о прохождении проверки знаний работником в реестре Минтруда
- Приоритеты: Must have (M), Should have (S), Could have (C), Won't have (W)

## Функциональные требования

### Загрузка данных (M)

1. **FR-001**: Система должна поддерживать ручной ввод данных о работнике через веб-интерфейс.
   - Поля: Фамилия, Имя, Отчество, Должность, СНИЛС, Номер программы, Номер протокола, Результат, Дата
   - Валидация СНИЛС - 11 цифр, автоформатирование "123-456-789 00"
   - Валидация программы - 1-29 (кроме 5), несколько через запятую
   - Валидация результат - "Удовлетворительно" или "Неудовлетворительно"

2. **FR-002**: Система должна поддерживать ввод данных об Учебном центре и Заказчике.
   - ИНН УЦ (10 или 12 цифр), Название УЦ
   - ИНН Заказчика (10 или 12 цифр), Название Заказчика
   - Сохранение между сессиями в JSON

3. **FR-003**: Система должна предоставлять справочник программ обучения.
   - Отображение списка прогр��мм �� номерами и названиями
   - Выбор программы кликом

4. **FR-004**: Система должна поддерживать загрузку XLSX файлов.
   - Поддержка форматов .xlsx
   - Валидация данных с отчётом об ошибках
   - Шаблоны: Фамилия, Имя, Отчество, СНИЛС, Должность, ИНН Заказчика, Наименование Заказчика, ИНН УЦ, Наименование УЦ, Результат, № программы, Дата, № протокола

5. **FR-005**: Система должна поддерживать загрузку XML файлов.
   - Импорт по XSD-схеме

6. **FR-006**: Система должна поддерживать загрузку XSD файла.
   - Валидация XML по загруженной XSD

7. **FR-007**: Система должна открывать ссылку на схему XSD.
   - Кнопка открывает https://akot.rosmintrud.ru/sout/info

8. **FR-008**: Система должна формировать шаблон XLSX файла.
   - Кнопка создаёт "Шаблон.xlsx"

### FR-009: Сохранение данных УЦ и Заказчика в JSON

- AC-1: Загрузка при старте из data/config.json
- AC-2: Сохранение при нажатии "Сохранить данные"
- AC-3: Структура JSON: tc_inn, tc_title, employer_inn, employer_title
- AC-4: При отсутствии - создание пустого файла

### Отображение данных (M)

9. **FR-010**: Система должна формировать перечень работников.
   - Таблица со всеми столбцами
   - Объединение/замена при новой загрузке
   - Уникальность по СНИЛС + программа

10. **FR-011**: Система должна отображать введенные данные.
    - N строк для N программ

11. **FR-012**: Система должна предоставлять редактирование.
    - Редактирование строки через форму

12. **FR-013**: Система должна предоставлять удаление.
    - Удаление строки с подтверждением

### Передача данных в Минтруд (M)

14. **FR-019**: Система должна поддерживать ввод и сохранение API ключа.
    - Поле для ввода API ключа (32 символа)
    - Сохранение в зашифрованном виде

15. **FR-020**: Система должна направлять XML на сервер Минтруда.
    - Выбор XML файла
    - Отправка на edu.rosmintrud.ru/api/set/push
    - Получение SetId

16. **FR-021**: Система должна запрашивать регистрационные номера по SetId.
    - Запрос на edu.rosmintrud.ru/api/GetEducatedPersonXML

17. **FR-022**: Система должна запрашивать данные по СНИЛС.
    - Поиск работника по СНИЛС

### Журнал проверки знаний (M)

18. **FR-023**: Система должна вести журнал проверок.
    - Сохранение истории отправок
    - Статусы: "ожидает", "получен"

19. **FR-024**: Система должна обновлять регистрационные номера.
    - Запрос по SetId и обновление записей

### Протокол проверки знаний (M)

20. **FR-025**: Система должна формировать протокол.
    - Заполнение шаблона Word данными комиссии и работников
    - Выбор протокола или "Все"

### Шифрование (M)

21. **FR-026**: Система должна шифровать конфиденциальные данные.
    - AES шифрование для API ключа, настроек прокси
    - Ключ на основе имени пользователя системы
