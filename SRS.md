# Требования к системе Excel-XML для передачи данных в Минтруд.

## Назначение

Система предназначена для генерации XML файлов с данными работников, обученных требованиям охраны труда согласно 2464 в целях автоматизации внесения информации о работниках в базу данных Минтруда и генерации протоколов проверки знаний с целью оптимизации времени работы специалистов по охране труда.

## Глоссарий

- Система - разрабатываемое ПО

- Вкладка - отдельное окно программы

- Учебный центр - организация, проводящее обучение

- Заказчик -  организация, в которой числится работник (работодатель)

- XSD файл - схема создания XML документа, соответствующая требованиям Минтруда, с сайта https://akot.rosmintrud.ru/sout/info

- сайт Минтруда - https://lkot.mintrud.gov.ru/ , раздел Обучение по охране труда.

- Приоритеты: Must have (M) , Should have (S)  ,Could have (C)  , Won't have (W)

- SetId - уникальный идентификатор загрузки данных в  систему Минтруда, возвращается сервером после успешной отправки XML.  Используется для последующего запроса регистрационных номероd

## Функциональные требования

### Загрузка данных (M)

1. **FR-001**: система должна поддерживать ручной ввод данных о работнике на вкладке "Внесение данных". (M)
   Описание: Пользователь заполняет форму работника вручную и сохраняет запись в системе.
   Обоснование: Позволяет завести запись без файлообмена.
   Критерии приемки:
   - AC-1: Есть поля для внесения данных: Фамилия, Имя, Отчество, Должность, СНИЛС, Номер программы, Номер протокола, Результат, Дата.
   - AC-2: При корректно заполненных полях запись создаётся, статус «Запись создана».
   - AC-3: При незаполненных обязательных полях система подсвечивает ошибки и не сохраняет.
   - AC-4: Валидация Фамилия, Имя, Отчество, Должность - только текст. При неправильном вводе - сообщение об ошибке ввода.
   - AC-5: Валидация СНИЛС - 11 цифр. Имеется возможность всьавить данные из буфера обмена. При неправильном вводе - сообщение об ошибке ввода после нажатия кнопки "Сохранить данные".
   - AC-6: Валидация Номер программы: числа от 1 до 26, за исключением 5. Знак ",".  Поддерживается запись в виде "1,2" и "1,2,". При неправильном вводе - сообщение об ошибке ввода после нажатия кнопки "Сохранить данные".
   - AC-7: Валидация Результат - только "Удовлетворительно" и "Неудовлетворительно". Формат поля - выпадающий список.
   - AC-8: при наличии в строке Номер программы более одной программы, разделенных запятыми, в систему вносится столько строк, сколько выбрано программ. Данные работника, УЦ, Работодателя повторяются во всех строках, уникальны номера программ. При дублировании - наличия строки с аналогичным СНИЛС и Номером программы - отображение ошибки с текстом "Выявлены аналогичные данные - х строк".
   - AC-9: при нажатии кнопку "Сохранить данные" в разделе "Ручной ввод" данные строк вносятся в память программы и отображаются во вкладке "Просмотр данных". В случае отсутствия данных в строках появляется ошибка "Заполните все строки". После внесения данных все поля, кроме "№ программы", очищаются.
   - AC-10: при нажатии на кнопку "Очистить" в разделе "Ручной ввод" данные всех строк очищаются.
   - AC-11: валидация Дата - дата меньше или равна текущей даты, формат ввода в ячейку ЧЧ.ММ.ГГГГ или ЧЧММГГГГ. В случае ошибки ввода - сообщение "Дата некорректна. Ведите корректную дату в формате ЧЧ.ММ.ГГГГ или ЧЧММГГГГ"
2. **FR-002**: система должна поддерживать ручной ввод данных об Учебном центре и Заказчике на вкладке "Внесение данных". (M)
   Описание: Пользователь вносит данные об учебном центре и работодателе вручную (ИНН и Название), и сохраняет запись в системе при нажатии на кнопку "Сохранить данные", расположенную под полями ввода.
   Обоснование: Позволяет внести обязательные данные для конвертации согласно схемы XSD.
   Критерии приемки:
   - AC-1: Имеются строки для внесения цифр : ИНН УЦ, ИНН Заказчика.
   - AC-2: имеются строки для ввода текста: Название УЦ, Название Заказчика.
   - AC-3: в строки возможно вставить данные из буфера обмена.
   - AC-4: внесенные данные сохраняются между сессиями.
   - AC-5: валидация ИНН - 10 или 12 цифр. В случае некорректного внесения - сообщение об ошибке "ИНН - только 10 или 12 цифр".
   - AC-6: в случае отсутствия данных в полях при нажатии кнопку "Сохранить данные" в разделе "Ручной ввод" появляется ошибка "Заполните данные УЦ/Работодателя".
3. **FR-003**: система должна предоставлять данные об имеющихся программах обучения на вкладке "Внесение данных".(M)
   Описание: При нажатии на кнопку "Справка", расположенную возле строки "Номер программы" раздела ручного ввода, открывается перечень программ (№№1-26, без №5). При двойном клике на программу ее номер вносится в строку "Номер программы"
   Обоснование: Позволяет внести обязательные данные путем их выбора для удобства пользователя
   Критерии приемки:
   - AC-1: возле строки "Номер программы" раздела ручного ввода имеется кнопка "Справка", при нажатии на которую отображается перечень номероав и наименований программ обучения.
   - AC-2: при выборе программы двойным кликом ее номер вносится в строку "Номер программы" с автоматическим добавлением "," в конце.
   - AC-3: возможно выбрать от одной до десяти программ обучения. При большем количестве - уведомление "Превышено количество программ для одного работника".
4. **FR-004:** система должна поддерживать загрузку XLSX (xls) файлов с данными работников на вкладке "Внесение данных".(M)
   Описание: Пользователь выбирает XLSX(xls) , система валидирует и создаёт/обновляет записи в программе.
   Обоснование: Массовый импорт ускоряет первичное наполнение.
   Критерии приемки:
   - AC-1: Успешный импорт корректного файла создаёт записи согласно шаблону.
   - AC-2: Для строк с ошибками формируется отчёт и строки пропускаются. Формат отчета - информационное окно с текстом "Количество строк с ошибками: Х"
   - AC-3: Логирование ошибок импорта
   - AC-4: в случае успешного импорта - сообщение "Успешно загружено.
   - AC-5: в случае ошибки - сообщение "Ошибка импорта"
   - AC-6: поддерживаемый шаблон XLSX(xls) должен содержать следующие столбцы: Фамилия, Имя, Отчество, СНИЛС, Должность, ИНН Заказчика, Наименование ЮЛ Заказчика, ИНН УЦ, Наименование УЦ, Результат,№ программы, Дата, № протокола.
5. **FR-005**: система должна поддерживать загрузку XML файлов с данными работников на вкладке "Внесение данных".(M)
   Описание: Импорт XML по XSD-схеме, валидация и создание/обновление записей.
   Обоснование: Массовый импорт ускоряет первичное наполнение.
   Критерии приемки:
   - AC-1: Файл, соответствующий XSD, импортируется без ошибок.
   - AC-2: При несоответствии XSD отображается список нарушений.
   - AC-3: Логирование ошибок импорта
   - AC-4: в случае успешного импорта - сообщение "Успешно загружено.
   - AC-5: в случае ошибки - сообщение "Ошибка импорта"
6. **FR-006**: система должна поддерживать загрузку XSD файла на вкладке "Внесение данных".(M)
   Описание: Импорт  XSD-схемы для валидации и создания/обновления записей.
   Обоснование: Создаваемые XML файлы должны соответствовать предоставляемой XSD, файл XSD может меняться
   Критерии приемки:
   - AC-1: Файл XSD импортируется без ошибок.
   - AC-2: загружаемые XML файлы валидируются по загруженному XSD
   - AC-3: Логгирование ошибок импорта
   - AC-4: загруженная схема XSD сохраняется в файлах приложения.    
   - AC-5: в случае успешного импорта - сообщение "Успешно загружено.
   - AC-6: в случае ошибки - сообщение "Ошибка импорта"
   - AC-7: сохраненная схема размещается в подразделе "schema" корневой директории программы.
7. **FR-007**: система должна направлять на сайт Минтруда с актуальной схемой XSD. (M)
   Описание: при нажатии на кнопку "Схема XSD" система открывает браузер со ссылкой "https://akot.rosmintrud.ru/sout/info"
   Обоснование: при необходимости обновления схемы XSD в случае ее изменения.
   Критерии приемки:

- AC-1: при нажатии на кнопку "Схема XSD" открывается браузер со ссылкой "https://akot.rosmintrud.ru/sout/info"

8. **FR-008**: система должна формировать шаблон xlsx файла для заполнения. (M)
   Описание: при нажатии на кнопку "Создать шаблон" система генерирует xlsx файл в корневом хранилище приложения.
   Обоснование: формирование шаблона, поддерживаемого программой
   Критерии приемки:

- AC-1: при нажатии на кнопку "Создать шаблон" система генерирует xlsx файл с именем "Шаблон.xlsx" со столбцами: Фамилия, Имя, Отчество, СНИЛС, Должность, ИНН Заказчика, Наименование ЮЛ Заказчика, ИНН УЦ, Наименование УЦ, Результат,№ программы, Дата, № протокола.
- AC-2: после создания файла система уведомляет пользователя окном уведомления "Шаблон создан. Открыть расположение файла?". В случае нажатия кнопки Открыть - открывается расположение файла (корневая папка программы), в случае нажатия кнопки Отмена - диалоговое окно закрывается.


### Отображение данных (M)

9. **FR-009**: система должна формировать на вкладке "Просмотр данных" перечень работников согласно внесенных данных из нескольких файлов различного типа и вручную. (M)
   Описание: создание перечня данных для конвертирования, полученных из разных источников
   Обоснование: возможность формирования данных из перечней данных.
   Критерии  приемки:
   - AC-1: в систему загружаются данные из файлов xlsx, xml, данные отображаются корректно
   - AC-2: при загрузке второго и далее файлов появляется диалоговое окно "что делать с данными" с кнопками "объединить, удалить старые, отменить загрузку". При нажатии "объединить" - новые данные добавляются к имеющимся, "удалить старые" - остаются только вновь добавленные данные, "отмена" - остаются имеющиеся данные.
   - AC-3: при объединении данных добавляются строки работников с уникальными СНИЛС и номерами программ. В случае выявления дублей приоритетными являются номера программ, затем - СНИЛС.
   - AC-4: на вкладке "Просмотр данных"  присутствует таблица со столбцами Фамилия, Имя, Отчество, СНИЛС, Должность, ИНН Заказчика, Наименование ЮЛ заказчика, ИНН УЦ, Наименование УЦ, Результат, № программы, Дата, № протокола.
   - AC-5: При нажатии на кнопку "Очистить", расположенную на вкладке "Просмотр данных", появляется диалоговое окно "Очистить все данные? Данные удалятся безвозвратно.". При нажатии ОК - данные в таблице на вкладке "Просмотр данных" очищаются полностью, при нажатии Отмена - окно закрывается.

10. **FR-010**: система должна отображать введенные данные на вкладке "Просмотр данных". (M)
      Описание: отображение загруженных и введенных вручную данных 
      Обоснование: Контроль введенных данных
      Критерии приемки:

   - AC-1: загруженные данные отображаются на вкладке "Просмотр данных"
   - AC-2: для работника, обученного по N программ, должно отображаться N строк с уникальными номерами программ, но одинаковыми данными пользователя
   - AC-3: при загрузке данных, уже имеющихся в программе (валидация по СНИЛС и Номеру программы), данные не загружаются , пользователь уведомляется об ошибке сообщением "Выявлены дубликаты".

11. **FR-011**: система должна предоставлять возможность редактирования внесенных в программу данных на вкладке "Просмотр данных". (M)
      Описание: редактирование данных во вкладке Просмотр данных
      Обоснование: исправление ошибок при их выявлении
      Критерии  приемки:

   - AC-1: при выборе строки с данными имеется возможность открытия окна редактирования.
   - AC-2: валидация данных в окне редактирования согласно требований FR-001
   - AC-3: при нажатии кнопки Сохранить в окне изменения в данных сохраняются. Сообщение не требуется.
   - AC-4: при нажатии Отмена внесенные данные не сохраняются. Сообщение не требуется.

12. **FR-012**: система должна предоставлять возможность удаления внесенных в программу данных на вкладке "Просмотр данных". (M)
      Описание: удаление строки данных во вкладке Просмотр данных
      Обоснование: удаление строки при необходимости
      Критерии  приемки:

   - AC-1: при выборе строки с данными имеется возможность выбора задачи "Удалить".
   - AC-2: при нажатии Удалить появляется окно с уведомлением "Вы уверены, что хотите удалить?"
   - AC-3: после подтверждения удаления строка с данными стирается. В случае отмены удаления окно закрывается, ничего не происходит.

Рекомендации к отправке набора записей через API
При работе с помощью ключа взаимодействия права пользователя соответствуют его
правам при работе через пользовательский интерфейс.
Рекомендации к отправке набора записей:
−запрос отправляется «Post» методом;
−для отправки запроса необходимо прикрепить два файла с расширениями
«.olot» и «.xml»;
− файлы передаются как часть формы, а не напрямую в теле запроса, то есть
надо использовать заголовок «Content-Type: multipart/form-data».
−файл с расширением «.xml» должен содержать корневой элемент «Request»,
внутри которого должны быть элементы: «ApiKey» и «NeedSend»;
−элемент «ApiKey» является обязательным и должен содержать строковый
ключ пользователя, взятый из профиля личного кабинета. Ключ должен состоять из 32
символов;
−элемент «NeedSend» необязателен. По умолчанию его значение равно false.
Этот элементуказывает, хочет ли пользователь отправить набор в РОЛ. Тип данных
элемента «NeedSend» - логический (bool). Если в отправляемом документе с расширением «.olot» есть файл с подписью «.sig», значение параметра устанавливается в true. Если «.olot» содержит только файл «.xml», значение параметра false или элемент «NeedSend» может быть не указан. Если пользователь добавляет в файл «.olot» файл с расширением «.sig», но значение «NeedSend» равно false, набор не будет отправлен в РОЛ.
Файл с расширением «.olot» является архивом, в котором должен находиться
документ в формате «.xml»
При успешном выполнении запроса будет возвращен файл с расширением «.xml»,
содержащий корневой элемент «Response». Внутри этого элемента будут три
дополнительных элемента: «SetId», «SendEducatedPerson» и «Message». Элемент «SetId» содержит номер созданного набора. Элемент «SendEducatedPerson» будет иметь значение true, если набор был успешно отправлен в РОЛ, и false, если отправка не была выполнена.
Элемент «Message» может содержать дополнительные комментарии или информацию.

В случае неуспешного выполнения запроса будет возвращен файл с расширением
«.xml», содержащий элемент «Error». Внутри этого элемента будут два дополнительных элемент: «StatusCode» и «Message». Элемент «StatusCode» содержит код статуса, указывающий на тип ошибки, а элемент «Message» содержит детализированное сообщение об ошибке, объясняющее причину неудачного выполнения запроса.
Запрос отправляется на адрес https://edu.rosmintrud.ru/api/set/push

## **BR-2: Загрузка данных на сайт Минтруда (без подписи)**

**Назначение**: Отправка XML файла с данными обученных работников в информационную  систему Минтруда через API без электронной подписи (для валидации или  тестовой отправки).



**Предусловия**:

- Сформирован и валидирован XML файл согласно XSD схемы
- Введен и сохранен корректный API ключ (32 символа)
- Установлено соединение с сервером Минтруда

**Алгоритм**:

1. **Подготовка запроса**:
   - Система читает XML файл из выбранного пользователем расположения
   - Повторно валидирует XML против XSD схемы из папки `/schema`
   - Проверяет наличие и корректность API ключа (32 символа)
2. **Формирование пакета данных**:
   - Создается файл `Request.xml` со структурой:

- ```
  xml<Request>
    <ApiKey>[32-символьный ключ]</ApiKey>
    <NeedSend>false</NeedSend>
  </Request>
  ```

- NeedSend = false означает, что подпись не требуется

- Файл с данными работников переименовывается в `data.xml`

**Создание ZIP архива**:

- Система создает временный ZIP архив с именем `upload_[timestamp].zip`
- В архив помещаются файлы:
  - `Request.xml` (метаданные запроса)
  - `data.xml` (данные обученных работников)

**Отправка POST запроса**:

- URL endpoint: `https://edu.rosmintrud.ru/api/setpush` (рабочая среда) или `https://edu-test.rosmintrud.ru/api/setpush` (тестовая среда)
- Метод: POST
- Content-Type: `application/zip`
- Body: бинарное содержимое ZIP файла
- Timeout: 30 секунд

**Обработка ответа**:

**Успешный ответ (HTTP 200)**:

```
xml<Response>
  <SetId>[уникальный идентификатор загрузки]</SetId>
  <SendEducatedPerson>true</SendEducatedPerson>
  <Message>Данные успешно загружены</Message>
</Response>
```

- Система сохраняет `SetId` во временное хранилище для последующего запроса регистрационных номеров
- Отображает пользователю: "Данные загружены на сервер"
- Логирует успешную операцию с timestamp, SetId и количеством записей

**Ответ с ошибкой (HTTP 4xx/5xx)**:

1. ```
   xml<Error>
     <StatusCode>[код ошибки]</StatusCode>
     <Message>[описание ошибки]</Message>
     <DateTime>[дата и время]</DateTime>
     <RequestId>[идентификатор запроса]</RequestId>
   </Error>
   ```

   - Система анализирует код ошибки:
     - 400: "Ошибка валидации XML. Проверьте соответствие схеме XSD"
     - 401: "Ошибка авторизации. Проверьте API ключ"
     - 500: "Ошибка сервера Минтруда. Повторите попытку позже"
   - Логирует ошибку с полным текстом ответа
   - Отображает пользователю: "Ошибка загрузки: [Message]"

2. **Постобработка**:

   - Удаление временного ZIP архива
   - Если отправка успешна и режим - рабочая среда:
     - SetId связывается с записями работников в журнале проверки знаний
     - Для каждой записи (СНИЛС + Программа) сохраняется ссылка на SetId для последующего получения рег.номеров

**Исключительные ситуации**:

- Timeout соединения → повторная попытка (максимум 2)
- Ошибка сети → уведомление "Нет соединения с сервером Минтруда"
- XML не прошел валидацию → блокировка отправки с указанием ошибок

**Критерии успеха**:

- Получен HTTP 200 с корректным SetId
- SetId сохранен в журнале для всех обработанных записей
- Логирование выполнено

**Ссылки на требования**: FR-017, FR-016, FR-013

- 6a. Ручное добавление работника → заполняет форму → добавляет к существующим

- Записи добавлены в журнал протоколов
