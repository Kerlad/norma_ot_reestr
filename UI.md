## 1. Общее описание

**Назначение:** Программа для автоматизации передачи данных о работниках, обученных требованиям охраны труда (постановление №2464), в информационную систему Минтруда России через API.

**Основные функции:**
- Ручной ввод данных о работниках
- Импорт данных из Excel (XLSX/XLS) и XML
- Валидация данных по XSD-схеме
- Отправка данных на сервер Минтруда
- Получение регистрационных номеров
- Формирование протоколов проверки знаний

## 2. Вкладка «Внесение данных»

### 2.1 Раздел «Данные УЦ и работодателя»

**Поля:**
| Поле | Обязательно | Валидация | Описание |
|------|-------------|------------|----------|
| ИНН УЦ | Да | 10 или 12 цифр | Индивидуальный номер налогоплательщика учебного центра |
| Название УЦ | Да | Текст | Полное наименование учебного центра |
| ИНН Заказчика | Да | 10 или 12 цифр | ИНН организации-работодателя |
| Название Заказчика | Да | Текст | Полное наименование организации |

**Кнопки:**
- **Сохранить данные** — сохраняет данные в `/data/org_settings.json`

### 2.2 Раздел «Загрузка данных»

**Поля:**
| Поле | Описание |
|------|----------|
| Выберите файл | Путь к файлу XLSX/XLS/XML |
| XSD схема | Путь к файлу XSD для валидации |

**Кнопки:**
- **Выбрать файл** — открывает диалог выбора файла данных
- **Выбрать XSD** — открывает диалог выбора файла XSD
- **Схема XSD** — открывает сайт https://akot.rosmintrud.ru/sout/info
- **Создать шаблон** — создает файл `Шаблон.xlsx` в корневой папке
- **Загрузить файл** — запускает импорт данных

**Результат загрузки:**
- При успехе: «Успешно загружено. Записей: X»
- При ошибках: «Ошибка импорта» с кнопкой «Показать ошибки»

### 2.3 Раздел «Ручной ввод»

**Поля (строка работника):**
| Поле | Обязательно | Валидация |
|------|-------------|-----------|
| Фамилия | Да | Только буквы, дефис, пробел |
| Имя | Да | Только буквы, дефис, пробел |
| Отчество | Нет | Только буквы, дефис, пробел |
| СНИЛС | Да | 11 цифр (автоформатируется в XXX-XXX-XXX XX) |
| Должность | Да | Текст |
| № программы | Да | 1-29 (кроме 5), через запятую |
| № протокола | Да | Текст |
| Дата | Да | ДД.ММ.ГГГГГ или ДДММГГГГ |
| Результат | Да | Выпадающий список: «Удовлетворительно», «Неудовлетворительно» |

**Кнопки:**
- **+** — добавить строку работника
- **Сохранить данные** — сохранить введенные данные в память программы
- **Очистить** — очистить все поля ввода
- **Справка** (рядом с № программы) — открыть справочник программ обучения

**Кнопка «Справка»:**
Открывает диалог со списком программ обучения (№1-29, кроме 5). Двойной клик добавляет номер в поле «№ программы».

## 4. Вкладка «Передача данных»

### 4.1 Раздел «API ключ»

**Поля:**
| Поле | Описание |
|------|----------|
| API ключ | 32-символьный ключ для доступа к API Минтруда |

**Кнопки:**
- **Вставить** — вставить ключ из буфера обмена
- **Сохранить** — сохранить ключ в зашифрованном виде
- **👁** — показать/скрыть ключ (зажать для просмотра)

### 4.2 Раздел «Настройки прокси»

**Режимы:**
| Режим | Описание |
|-------|----------|
| Без прокси | Прямое подключение к интернету |
| Авто (системные) | Использовать прокси из настроек Windows |
| Вручную | Указать прокси вручную |

**Поля (режим «Вручную»):**
| Поле | Описание |
|------|----------|
| Адрес прокси | URL прокси (например, proxy.example.com:3128) |
| Логин | Имя пользователя для авторизации на прокси |
| Пароль | Пароль для авторизации |

**Чекбокс «TLS верификация»:**
- **Выключено** (по умолчанию) — для корпоративных сетей с SSL-инспекцией
- **Включено** — для безопасного соединения напрямую

**Кнопки:**
- **Сохранить настройки** — сохранить настройки прокси
- **Тест подключения** — проверить соединение с edu.rosmintrud.ru
- **👁 Показать пароль прокси** — зажать для просмотра пароля

### 4.3 Раздел «Отправка XML»

**Поля:**
| Поле | Описание |
|------|----------|
| XML файл | Путь к файлу XML |

**Кнопки:**
- **Выбрать** — выбрать файл XML
- **Отправить XML на сервер** — загрузить данные на сервер Минтруда

**Результат:**
- При успехе: «Данные загружены на сервер. Запишите номер набора: XXXX»
- При ошибке: «Ошибка загрузки: [описание ошибки]»

### 4.4 Раздел «Запрос по SetId»

**Поля:**
| Поле | Описание |
|------|----------|
| Введите номер набора (SetId) | Идентификатор, полученный при отправке |

**Кнопки:**
- **Запросить номера** — получить регистрационные номера

**Результат:**
- Сохранение XLSX-файла с регистрационными номерами

**Поля:**
| Поле | Описание |
|------|----------|

## 7. Логика работы системы

### 7.1 Поток данных

```
Ввод данных → Валидация → Хранилище (pandas DataFrame)
        ↓
Конвертация в XML → Валидация по XSD
        ↓
Отправка на сервер Минтруда (API)
        ↓
Получение SetId → Сохранение в Журнал
        ↓
Запрос регистрационных номеров (по SetId или СНИЛС)
        ↓
Обновление Журнала → Формирование протокола
```

### 7.2 Валидация

**СНИЛС:**
- 11 цифр
- Форматирование: XXX-XXX-XXX XX
- Автоудаление дефисов и пробелов перед проверкой

**ИНН:**
- 10 цифр (для ИП) или 12 цифр (для юрлиц)

**Номер программы:**
- 1-29, кроме 5
- Несколько через запятую (1,2,3)

### 7.3 Шифрование данных

| Данные | Метод | Файл |
|--------|-------|------|
| API ключ | Fernet (AES) | /data/api_key.json |
| Журнал | Fernet (AES) | /data/exam_journal.json |
| Настройки прокси | Fernet (AES) | /data/proxy_settings.json |

### 7.4 Прокси-поддержка

**Режимы:**
- Без прокси — прямое подключение
- Авто — системные настройки Windows
- Вручную — указанные параметры

**NTLC-аутентификация:** Поддерживается для логинов вида `DOMAIN\login`

## 8. Форматы данных

### 8.1 Формат XLSX (импорт/экспорт)

| Колонка | Обязательно | Пример |
|---------|--------------|--------|
| Фамилия | Да | Иванов |
| Имя | Да | Иван |
| Отчество | Нет | Иванович |
| СНИЛС | Да | 123-456-789 00 |
| Должность | Да | Слесарь |
| ИНН Заказчика | Нет | 1234567890 |
| Название ЮЛ Заказчика | Нет | ООО "Рога и копыта" |
| ИНН УЦ | Нет | 0987654321 |
| Название УЦ | Нет | УЦ "Профессионал" |
| Результат | Да | Удовлетворительно |
| № программы | Да | 1 |
| Дата | Да | 15.04.2026 |
| № протокола | Да | 1 |

### 8.2 Формат XML

Соответствует XSD-схеме Минтруда. Структура:
```xml
<EducatedPersons>
    <Person>
        <Worker>
            <LastName>...</LastName>
            <FirstName>...</FirstName>
            <MiddleName>...</MiddleName>
            < Snils>...</Snils>
            <Position>...</Position>
        </Worker>
        <Employer>
            <INN>...</INN>
            <Title>...</Title>
        </Employer>
        <TrainingCenter>
            <INN>...</INN>
            <Title>...</Title>
        </TrainingCenter>
        <Program>1</Program>
        <Date>15.04.2026</Date>
        <ProtocolNumber>1</ProtocolNumber>
        <Result>Удовлетворительно</Result>
    </Person>
</EducatedPersons>
```

## 9. Безопасность

### 9.1 Хранение данных

- Все конфиденциальные данные шифруются алгоритмом Fernet (AES-128)
- Ключ шифрования привязан к имени пользователя Windows
- Пароли не логируются

### 9.2 Защита от подглядывания

- API-ключ скрыт по умолчанию (показать при зажатой кнопке)
- Пароль прокси скрыт по умолчанию (показать при зажатой кнопке)

### 9.3 TLS

- По умолчанию выключено для работы через корпоративные прокси с SSL-инспекцией
- Включается чекбоксом «TLS верификация»
