### 2.3. Замечание по TLS (№4)

В файлах `api/mintrud_api.py:209` и `api/mintrud_api.py:432` параметр `verify=True` задан жёстко:

```python
response = session.post(
    API_URL,
    ...
    verify=True,  # ← Жёстко, не использует ENABLE_TLS_VERIFY
    timeout=60
)
```

При этом чекбокс в интерфейсе (`data_transfer_tab.py`) управляет переменной `ENABLE_TLS_VERIFY`, но она **не применяется** к самим API-вызовам. Это означает, что даже при отключённом чекбоксе TLS проверка **включена**, а при включённом — поведение не меняется.

**Рекомендация:** Заменить `verify=True` на `verify=ENABLE_TLS_VERIFY` в вызовах `session.post()`.

## 4. Безопасность передачи персональных данных

### 4.1. Какие данные передаются

На сервер Минтруда (`https://edu.rosmintrud.ru`) передаются:

- ФИО работника
- СНИЛС (11 цифр)
- Должность
- Номер программы обучения (1–29)
- Результат проверки знаний
- Дата экзамена
- Номер протокола
- Данные об учебном центре (ИНН, название)
- Данные о работодателе (ИНН, название)

Эти данные являются **персональными данными** в понимании 152-ФЗ «О персональных данных».

### 4.4. Механизм шифрования

Шифрование реализовано с использованием **Fernet (AES) из библиотеки `cryptography`**:

```python
# utils/crypto.py
def _get_derive_key():
    username = os.environ.get('USERNAME', 'default_user').encode('utf-8')
    return hashlib.sha256(username).digest()  # ← Слабое место

# Генерация ключа Fernet
fernet_key = base64.urlsafe_b64encode(key)
fernet = Fernet(fernet_key)

# Шифрование
encrypted = fernet.encrypt(value.encode('utf-8'))
```

**Примечание:** Ключ шифрования основан только на имени пользователя Windows (без соли). Это ослабляет защиту:

- Любой пользователь с тем же именем может расшифровать данные.
- Возможна атака по радужным таблицам.
- Рекомендуется использовать `keyring` или PBKDF2/Argon2.

### 4.5. Передача данных на сервер —流程

```
1. Формирование Request.xml (ApiKey + NeedSend=false)
2. Упаковка Data.xml в ZIP-архив data.olot
3. multipart/form-data POST на https://edu.rosmintrud.ru/api/set/push
4. Сервер возвращает SetId (идентификатор набора)
5. Запрос регистрационных номеров по SetId или СНИЛС
```

Данные передаются в HTTP-теле:
- `Request.xml` — содержит API-ключ (не персональные данные)
- `data.olot` — ZIP-архив с `Data.xml` (персональные данные)
