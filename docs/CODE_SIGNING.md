# Цифровая подпись «Норма ОТ» — инструкция для ИТ-службы

Документ для системных администраторов организаций, которые разворачивают
программу **«Норма ОТ: Реестр обучения»** на рабочих местах специалистов по охране труда.

---

## 1. Что подписано и чем

Начиная со сборки, выпущенной после 20.10.2026, исполняемый файл `NormaOT_Reestr.exe`
подписан **самоподписанным** сертификатом разработчика:

| Параметр | Значение |
|---|---|
| Субъект | `CN=NormaOT (Кривоносов Д.А.), O=NormaOT, C=RU` |
| Издатель | тот же (самоподписанный) |
| Отпечаток SHA-1 | `981BDD1AEC938BD5BA0CAA2D84BDFB44CB6C83CB` |
| Алгоритм | RSA 3072 / SHA-256 |
| Действует до | 20.10.2036 |
| Файл открытой части | [`docs/signing/NormaOT_CodeSigning.cer`](signing/NormaOT_CodeSigning.cer) |
| SHA-256 файла `.cer` | `E9A5F298230A3385A35924568E70007A7D941C07B5CC45A33D001D43DB896271` |

Подпись содержит **метку времени** (RFC 3161), поэтому остаётся действительной и после
окончания срока действия сертификата.

### Честное предупреждение

Сертификат **не выдан публичным удостоверяющим центром**. Это значит:

- Windows по умолчанию ему **не доверяет**: в свойствах файла подпись видна, но помечена
  как недоверенная, а SmartScreen продолжит предупреждать обычных пользователей.
- Подпись **не заменяет** проверку происхождения файла. Она даёт две вещи: гарантию, что
  файл не изменён после сборки, и возможность вашей организации один раз принять решение
  о доверии издателю.
- Покупной сертификат (OV/EV) пока не приобретён: разработчик — физическое лицо, а такие
  сертификаты в настоящее время выдаются юридическим лицам и ИП, с обязательным хранением
  ключа на аппаратном носителе. Как только сертификат появится, сборки будут подписываться им,
  и эта инструкция станет не нужна.

**Устанавливайте сертификат в доверенные, только если ваша организация осознанно доверяет
разработчику.** Доверие корневому сертификату означает, что любой файл, подписанный этим
ключом, будет считаться доверенным на ваших машинах.

## 2. Перед установкой: проверьте сертификат

Файл `.cer` берите **из репозитория** `https://github.com/Kerlad/Excel_to_XML`
(`docs/signing/NormaOT_CodeSigning.cer`) или из архива сборки, затем сверьте отпечаток:

```powershell
Get-FileHash .\NormaOT_CodeSigning.cer -Algorithm SHA256
(New-Object System.Security.Cryptography.X509Certificates.X509Certificate2 ".\NormaOT_CodeSigning.cer").Thumbprint
```

Значения должны совпасть с таблицей выше. Отпечаток желательно подтвердить у разработчика
по независимому каналу (почта `denis.krv@yandex.ru`, сайт `normaot.ru`) — это защищает от
подмены файла при скачивании.

Проверить подпись самого EXE:

```powershell
Get-AuthenticodeSignature .\NormaOT_Reestr.exe | Format-List Status, StatusMessage, SignerCertificate
```

До установки сертификата статус будет `UnknownError` («цепочка не доверена»), после —
`Valid`. Если статус `HashMismatch` — файл повреждён или изменён, **не запускайте его**.

## 3. Установка на одной машине (проверка)

От имени администратора:

```powershell
Import-Certificate -FilePath .\NormaOT_CodeSigning.cer -CertStoreLocation Cert:\LocalMachine\Root
Import-Certificate -FilePath .\NormaOT_CodeSigning.cer -CertStoreLocation Cert:\LocalMachine\TrustedPublisher
```

- **Root** («Доверенные корневые центры сертификации») — нужен, чтобы цепочка проверялась:
  сертификат самоподписанный, то есть сам себе корень.
- **TrustedPublisher** («Доверенные издатели») — нужен, если в организации действуют
  AppLocker, WDAC или политики запуска по издателю.

Проверка: `Get-AuthenticodeSignature .\NormaOT_Reestr.exe` должен показать `Valid`.

## 4. Массовое развёртывание

### Групповые политики (GPO)

1. `Computer Configuration → Policies → Windows Settings → Security Settings → Public Key Policies`.
2. В разделе **Trusted Root Certification Authorities** → *Import* → выберите `.cer`.
3. То же самое в разделе **Trusted Publishers**.
4. Область применения ограничьте группой компьютеров, где реально нужна программа.

### Microsoft Intune

Профиль конфигурации → *Templates → Trusted certificate* → загрузите `.cer`, место хранения
**Computer certificate store – Root**; вторым профилем при необходимости — Trusted Publishers.

### Вручную/скриптом при установке

Команды из раздела 3 можно включить в скрипт развёртывания программы; требуются права
администратора.

## 5. Запуск без установки сертификата

Если устанавливать сертификат нельзя, программа всё равно работает. При первом запуске
Windows покажет окно SmartScreen: **«Подробнее» → «Выполнить в любом случае»**.

Перед этим проверьте SHA-256 скачанного архива — контрольная сумма публикуется на
`normaot.ru` и в `CHANGELOG.md`:

```powershell
Get-FileHash .\NormaOT-Reestr.zip -Algorithm SHA256
```

## 6. Отзыв доверия

Если доверие нужно снять (смена политики, компрометация ключа разработчика):

```powershell
Get-ChildItem Cert:\LocalMachine\Root, Cert:\LocalMachine\TrustedPublisher |
    Where-Object { $_.Thumbprint -eq "981BDD1AEC938BD5BA0CAA2D84BDFB44CB6C83CB" } |
    Remove-Item
```

Через GPO — удалите сертификат из соответствующих разделов политики.

Самоподписанный сертификат **не имеет списка отзыва (CRL/OCSP)**: отозвать его централизованно
нельзя, снять доверие можно только удалением из хранилищ. Это ещё одна причина ограничивать
область действия политики.

## 7. Что программа делает с данными (кратко)

Для согласования с вашей службой информационной безопасности:

- данные хранятся локально в `%APPDATA%\NormaOT`, ФИО и СНИЛС шифруются (Fernet),
  ключ защищён Windows DPAPI, дополнительно может быть задана парольная фраза;
- сеть используется только для обмена с реестром Минтруда (`edu.rosmintrud.ru`);
  телеметрии и отправки данных разработчику нет;
- поддерживаются корпоративные прокси и TLS-инспекция (с подтверждением пользователя);
- ведётся журнал аудита с HMAC-цепочкой, его целостность проверяется в программе.

Подробности — `README.md`, `docs/SECURITY.md`, `docs/HARDENING.md`.
