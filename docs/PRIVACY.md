# Политика обработки персональных данных (ИСПДн)

**Проект:** Excel_to_XML
**Версия:** 3.0.0
**Дата:** 22.05.2026
**Гриф:** ДСП (для служебного пользования)

---

## 1. Какие ПДн обрабатываются

### 1.1. Перечень обрабатываемых данных

| Поле | Сущность | Категория ПДн | Обязательность | Шифрование в БД |
|------|----------|---------------|----------------|-----------------|
| Фамилия | Сотрудник | Прямая идентификация | Да | Fernet AES-128-CBC |
| Имя | Сотрудник | Прямая идентификация | Да | Fernet AES-128-CBC |
| Отчество | Сотрудник | Прямая идентификация | Нет | Fernet AES-128-CBC |
| СНИЛС | Сотрудник | Прямая идентификация | Да | Fernet AES-128-CBC |
| Должность | Сотрудник | Косвенная идентификация | Да | Нет (plaintext) |
| ИНН Заказчика | Организация | Косвенная идентификация | Да | Нет |
| Название Заказчика | Организация | Косвенная идентификация | Да | Нет |
| Программа обучения | Сотрудник | Иные данные | Да | Нет |
| Дата экзамена | Сотрудник | Иные данные | Да | Нет |
| Результат | Сотрудник | Иные данные | Да | Нет |
| Номер протокола | Сотрудник | Иные данные | Нет | Нет |
| Рег. номер (baseNo) | Сотрудник | Иные данные | Нет | Нет |

### 1.2. НЕ обрабатываются

- Биометрические данные
- Специальные категории ПДн (здоровье, судимость, религия, etc.)
- Данные о членах семьи
- Данные о банковских счетах
- Фотографии / видео / аудио
- Геолокация

---

## 2. Цель обработки

Обработка ПДн осуществляется для:

1. **Исполнения обязанностей по ТК РФ** — учёт и контроль обучения работников по охране труда
2. **Исполнения Постановления №2464** — передача сведений об обучении в реестр обученных лиц Минтруда России
3. **Формирования отчётности** — протоколы проверки знаний, сводные отчёты, планы обучения
4. **Контроля периодичности** — отслеживание сроков переобучения

---

## 3. Правовое основание

Обработка ПДн осуществляется **БЕЗ согласия субъекта** на основании:

| НПА | Статья | Обоснование |
|-----|--------|-------------|
| 152-ФЗ | ст.6 ч.2 п.1 | Обработка необходима для исполнения обязанностей, возложенных на оператора законодательством РФ |
| 152-ФЗ | ст.6 ч.2 п.5 | Обработка необходима для исполнения трудового договора |
| ТК РФ | ст.14, 86-90 | Обработка в целях охраны труда и обеспечения безопасности |
| Постановление №2464 | пп. «е» п. 37 | Обязанность работодателя передавать сведения об обучении в Минтруд |

**Важно:** Оператор (работодатель) обязан ознакомить работников с фактом обработки их ПДн в рамках исполнения Постановления №2464. Согласие на обработку НЕ требуется, но уведомление — обязательно (ст. 18.1 152-ФЗ).

## 4. Где хранятся ПДн

### 4.1. Локальное хранение

| Хранилище | Путь | Защита |
|-----------|------|--------|
| SQLite БД | `%APPDATA%/Excel_to_XML/data/app_data.db` | Полевое шифрование Fernet (ФИО, СНИЛС) |
| Мастер-ключ | `%APPDATA%/Excel_to_XML/master.key` | Windows DPAPI (CryptProtectData) |
| Метаданные ключа | `%APPDATA%/Excel_to_XML/master.key.json` | HMAC-SHA256 integrity |
| API-ключ | `%APPDATA%/Excel_to_XML/api_key.json` | Fernet-шифрование |
| Proxy-credentials | `%APPDATA%/Excel_to_XML/proxy_settings.json` | Fernet-шифрование |
| Логи | `%APPDATA%/Excel_to_XML/log/*.log` | Маскировка ПДн (SensitiveDataFilter) |
| Временные файлы | `%TEMP%/excel_xml_secure_<UUID>/` | ACL-restricted, secure delete |

### 4.2. Передача

| Направление | Канал | Формат | Защита |
|-------------|-------|--------|--------|
| API Минтруда | HTTPS/TLS 1.2+ | XML (plaintext ПДн) | TLS verify=True |
| XML-экспорт | Локальный файл | XML (plaintext ПДн) | Нет (рекомендован BitLocker) |
| XLSX-экспорт | Локальный файл | XLSX (plaintext ПДн) | Нет (рекомендован BitLocker) |
| Backup БД | Локальный файл | SQLite (encrypted fields) | Полевое шифрование |
| Backup ключей | ZIP-архив | master.key + .json | PKWARE ZipCrypto (⚠️ слабое) |

## 5. Как защищаются ПДн

### 5.1. В покое (at rest)

| Уровень | Технология | Назначение |
|---------|------------|------------|
| Приложение | Fernet (AES-128-CBC + HMAC) | Полевое шифрование ФИО, СНИЛС |
| ОС | Windows DPAPI | Защита мастер-ключа |
| ОС | BitLocker (рекомендован) | Шифрование диска |
| ОС | NTFS permissions | Ограничение доступа к файлам |

### 5.2. В передаче (in transit)

| Канал | Протокол | Защита |
|-------|----------|--------|
| API | HTTPS | TLS 1.2+ verify=True |
| Прокси | NTLM/Kerberos | Encrypted authentication |

### 5.3. В логах

| Тип | Фильтрация | Паттерны |
|-----|------------|----------|
| app.log | SensitiveDataFilter | 27+ паттернов (SNILS, ФИО, паспорта, телефоны, email, API-ключи, JWT, пароли) |
| error.log | SensitiveDataFilter | Аналогично + маскировка traceback |
| audit.log | SensitiveDataFilter | Без ПДн по дизайну |

### 5.4. В памяти

- Мастер-ключ хранится в module-level global (не зануляется) ⚠️
- LRU-кэш encrypt/decrypt (до 2000 записей, ключи кэша — plaintext) ⚠️
- Пароль passphrase в global переменной (не зануляется) ⚠️
- VirtualLock НЕ реализован (docstring не соответствует коду) ⚠️

## 6. Сроки хранения

| Тип данных | Текущий срок | Рекомендуемый срок |
|------------|--------------|-------------------|
| Данные сотрудников | До ручного удаления | Период работы + 3 года |
| Журнал отправок | Постоянно | 5 лет |
| Логи приложения | Ротация 5×5MB | 5×5MB (текущий) |
| Резервные копии | До 5 копий | До 5 копий + выгрузка |
| Мастер-ключ | Весь срок эксплуатации | Весь срок + backup |

**Примечание:** Автоматическое удаление по сроку хранения (retention policy) **не реализовано**. Оператор должен удалять данные вручную.

## 7. Ограничения доступа

### 7.1. Технические ограничения

- Приложение защищено passphrase (PBKDF2, 600K итераций)
- Приложение блокируется при бездействии (таймаут настраивается)
- Мастер-ключ защищён DPAPI (привязка к учётной записи Windows)
- Файлы ключей имеют ACL-ограничения (только текущий пользователь)

### 7.2. Отсутствующие ограничения

- Нет ролевой модели (один оператор = полный доступ)
- Нет ограничения попыток ввода passphrase
- Нет разделения прав на чтение/запись/удаление/экспорт

## 8. Удаление данных

| Сценарий | Метод | Secure delete? |
|----------|-------|----------------|
| Удаление одной записи | SQL DELETE | ❌ Нет |
| Удаление всех данных | SQL DELETE | ❌ Нет |
| Удаление по сроку | ❌ Не реализовано | ❌ |
| Удаление при уходе сотрудника | Ручное | ❌ |

**Важно:** SQL DELETE не гарантирует безвозвратного удаления на SSD/NTFS.
Рекомендуется шифрование диска (BitLocker) — удаление ключа шифрования эквивалентно безвозвратному удалению.

## 9. Защита экспорта

| Тип экспорта | ПДн в открытом виде | Шифрование | Рекомендация |
|-------------|---------------------|------------|--------------|
| XML (в Минтруд) | Да | Нет (требуется Минтруду) | BitLocker |
| XLSX (отчёт) | Да | Нет | BitLocker |
| Backup БД | Нет (полевое шифрование) | Нет | BitLocker |
| Backup ключей | Да (ключи) | PKWARE ZipCrypto | Замена на AES-256 |

## 10. Ответственность

### 10.1. Оператор (работодатель) обязан

- Назначить ответственного за обработку ПДн
- Уведомить Роскомнадзор об обработке
- Утвердить Политику обработки ПДн
- Ознакомить работников с обработкой их ПДн
- Обеспечить защиту рабочего места (BitLocker, антивирус, обновления)
- Проводить инструктаж операторов

### 10.2. Приложение НЕ заменяет

- Организационные меры (политики, приказы)
- Физическую защиту рабочего места
- Защиту ОС (антивирус, firewall, BitLocker)
- Контроль доступа к помещению

---

## 11. Уведомление субъектов

Обработка ПДн осуществляется без согласия, но оператор обязан уведомить субъектов (работников) о:

1. Факте обработки их ПДн
2. Правовом основании обработки (Постановление №2464)
3. Целях обработки (передача в реестр Минтруда)
4. Перечне обрабатываемых данных
5. Сроках хранения
6. Правах субъекта (доступ, уточнение, удаление)

Рекомендуемая форма уведомления — Приложение к трудовому договору или дополнительное соглашение.
