# Техническое задание на разработку системы контроля обучения по охране труда

## 1. Общие положения

### 1.1. Цель проекта
Создать десктопное приложение (PySide6) для учета и контроля обучения сотрудников по охране труда в соответствии с Постановлением Правительства РФ № 2464. Приложение обеспечивает внесение данных о сотрудниках, прошедших обучение, формирование XML для передачи в реестр Минтруда (edu.rosmintrud.ru), хранение истории проверок знаний, формирование протоколов проверки знаний, а также сводный анализ статуса обучения сотрудников с возможностью запроса актуальных данных из реестра Минтруда.

### 1.2. Основные пользователи
Один пользователь с полным доступом ко всем данным и функциям приложения. Приложение не имеет встроенной системы авторизации — персональные данные защищены полевым шифрованием (Fernet + DPAPI).

### 1.3. Ограничения
- При наличии доступа к Интернету — интеграция с API Минтруда (edu.rosmintrud.ru)

## 2. Функциональные требования

### 2.1. Вкладка "Внесение данных"

**Назначение:** Ввод данных УЦ и работодателя, загрузка данных сотрудников из Excel/XML, ручной ввод записей о прохождении обучения.

**Разделы:**

**2.1.1. Данные УЦ и работодателя**
- ИНН УЦ (обязательное, 10 цифр)
- Наименование УЦ (обязательное)
- ИНН Заказчика (обязательное, 10 цифр)
- Наименование Заказчика (обязательное)
- Кнопка "Сохранить данные" — данные шифруются и сохраняются в `data/org_settings.json`
- При загрузке Excel пустые поля ИНН/наименования автоматически заполняются из сохранённых настроек

**2.1.2. Загрузка данных**
- Поддерживаемые форматы: .xlsx, .xml (RegistrySet)
- Кнопка "Выбрать файл" — открывает диалог выбора файла
- Кнопка "Загрузить файл" — запускает импорт:
  - XLSX: колонки `Фамилия | Имя | Отчество | СНИЛС | Должность | ИНН Заказчика | Наименование ЮЛ Заказчика | ИНН УЦ | Наименование УЦ | Результат | № программы | Дата | № протокола`
  - XML: парсинг RegistrySet по XSD-схеме
  - Валидация: СНИЛС (11 цифр), программа (1-29, кроме 5), результат (Удовлетворительно/Неудовлетворительно), дата (не в будущем)
  - Поддержка нескольких программ через запятую в одной ячейке (создаётся несколько записей)
  - Если данные уже загружены — диалог: объединить (пропуская дубли по СНИЛС+программа) или заменить
- Кнопка "Создать шаблон" — генерирует .xlsx с заголовками для заполнения
- Сигнал `data_loaded.emit(records, merge_mode)` — передаёт данные на вкладку "Просмотр данных"

**2.1.3. Ввод данных работника (ручной)**
- Поля: Фамилия, Имя, Отчество, СНИЛС (11 цифр), Должность, Номер программы (1-29, несколько через запятую), Номер протокола, Результат (выпадающий список), Дата (ДД.ММ.ГГГГ)
- Кнопка "Справка" — показывает перечень программ (двойной клик вставляет номер)
- Кнопка "Сохранить данные" — добавляет запись
- Валидация: обязательные поля, формат СНИЛС, корректность программы, дата не в будущем

### 2.2. Вкладка "Просмотр данных"

**Назначение:** Табличное отображение загруженных/введённых данных, редактирование, удаление, конвертация в XML.

**Функционал:**
- Таблица с колонками: Фамилия, Имя, Отчество, СНИЛС, Должность, ИНН заказчика, Наименование заказчика, ИНН УЦ, Наименование УЦ, Результат, № программы, Дата, № протокола
- Контекстное меню (правый клик): "Редактировать" (открывает диалог), "Удалить" (с подтверждением)
- Кнопка "Очистить" — удаляет все данные (с подтверждением)
- Кнопка "Конвертировать" — экспорт данных в XML-файл:
  - Загружает настройки организации из `org_settings.json`
  - Формирует RegistrySet XML по XSD-схеме (`schema/educated_person_import_v1.0.9.xsd`)
  - Диалог сохранения .xml

**Персистентность:**
- Данные автоматически сохраняются в `data/app_data.db` (таблица `workers_data`) при каждом изменении
- Автозагрузка при старте приложения

### 2.3. Вкладка "Передача данных"

**Назначение:** Отправка XML в Минтруд, запрос регистрационных номеров, поиск по СНИЛС.

**Разделы:**

**2.3.1. API ключ**
- Поле ввода API-ключа (32 символа, из кабинета edu.rosmintrud.ru)
- Кнопка "Сохранить ключ" — шифрованное сохранение в `data/api_key.json`
- Валидация: длина 32 символа

**2.3.2. Настройки прокси**
- Режимы: "Без прокси", "Авто (системные)", "Вручную"
- При ручном режиме: URL прокси, логин, пароль (шифруется)
- Чекбокс "Проверять TLS" (для корпоративных прокси с SSL-инспекцией)
- Поддержка NTLM, Kerberos/Negotiate, Basic-аутентификации

**2.3.3. Отправка XML**
- Выбор XML-файла (кнопка "Выбрать XML")
- Кнопка "Отправить XML на сервер" — формирует multipart-запрос (Request.xml + data.olot) и отправляет на `edu.rosmintrud.ru/api/set/push`
- При успехе: получение SetId, уведомление, передача записей в "Журнал проверки знаний"
- При ошибке: отображение кода и сообщения об ошибке

**2.3.4. Запрос по SetId**
- Поле ввода SetId
- Кнопка "Запросить номера" — пагинированный запрос к `edu.rosmintrud.ru/api/GetEducatedPersonXML`
- Результат: экспорт в XLSX с колонками `Номер записи в реестре | ФИО | СНИЛС | Должность | ИНН работодателя | Наименование работодателя | Номер программы | Название программы | Номер протокола | Дата | Зачёт`
- Автоматическое обновление baseNo в "Журнале проверки знаний"

**2.3.5. Запрос по СНИЛС**
- Поле ввода СНИЛС
- Кнопка "Найти" — запрос к API по СНИЛС
- Отображение найденных записей

### 2.4. Вкладка "Журнал проверки знаний"

**Назначение:** Хранение и просмотр истории отправок XML на сервер Минтруда, отслеживание регистрационных номеров.

**Модель данных (JournalRecord):**
- `uuid` — уникальный идентификатор записи
- `send_date` — дата/время отправки
- `set_id` — идентификатор набора от сервера
- `xml_file` — путь к отправленному XML
- `last_name, first_name, middle_name` — ФИО
- `snils` — СНИЛС (формат "123-456-789 00")
- `position` — должность
- `program_id` — номер программы ("1"-"29")
- `program_title` — название программы
- `exam_date` — дата экзамена
- `protocol` — номер протокола
- `result` — результат
- `base_no` — регистрационный номер (заполняется после запроса по SetId)
- `status` — "pending" (ожидает) / "received" (получен)

**Функционал:**
- Таблица с колонками: Дата отправки, SetId, ФИО, СНИЛС, Должность, Программа, Дата экзамена, Протокол, Результат, Рег. номер, Статус
- Цветовая индикация: "pending" — оранжевый, "received" — зелёный
- Панель фильтрации: поиск по ФИО/СНИЛС, фильтр по SetId, статусу, диапазону дат отправки
- Кнопка "Экспорт в XLSX" — выгрузка отфильтрованных записей
- Кнопка "Удалить" — удаление выбранных записей
- Контекстное меню: "Удалить"
- Хранение: `data/app_data.db` (таблица `exam_journal`)
- Менеджер: `JournalManager` (CRUD, поиск, фильтрация, обновление baseNo по SetId)

### 2.7. Вкладка "Сводка по сотрудникам"

**Назначение:** Расширенный анализ статуса обучения сотрудников с интеграцией с реестром Минтруда. Вкладка загружает данные о работниках из записей, загруженных посредством импорта EXCEL файла, или внесенных вручную. 

Отображает статус обучения по каждой программе и позволяет запрашивать актуальные данные из реестра Минтруда по СНИЛС.

**Источники данных:**
- Ручной ввод данных работника
- Импорт EXCEL файла
- API Минтруда (`query_by_snils`) — запрос актуальных данных о прохождении обучения из реестра по СНИЛС  по внесенным в таблицу работникам



**Ручной ввод:** 

отдельный раздел, аналогичен разделу Ручной ввод вкладки Ввод данных.

Строки

- ФИО (Фамилия + Имя + Отчество)
- СНИЛС
- Должность
- Программы направления на обучения (аналогично Справка раздела Ручной ввод вкладке Ввод данных - при нажатии появляется окно, двойной клик на программе добавляет ее в список)
- Кнопка Добавить запись
- Кнопка Отмена



**Поля таблицы:**

- ФИО (Фамилия + Имя + Отчество)

- СНИЛС

- Должность

- Потребность в обучении по программам. Скрытый, для импорта. Данные в формате "1;2;3;6"

- Программы обучения (номер ) - (данные столбцы выбираются пользователем в фильтре). Максимум 6 программ одновременно. По умолчанию отображаются программы №1, 2, 3, 4, 18, 23.

  Для каждой выбранной программы - три столбца (подраздела)

  - Потребность в обучении - значения 1 или 0 (true или false). Если 0 - остальные подразделы не учитываются при определении статуса.

  - Дата обучения (из ответа API)

  - Номер протокола (из ответа API)

  - Регистрационный номер в реестре (из ответа API -baseNo)

    данные находятся в одной ячейке, каждая на новой строке

- Статус (на основе свежести данных) - выделение ячейки Программы обучения (номер):
  - **Не обучен** — пустой результат - красная заливка
  - **Обучен** — дата обучения в актуальном периоде - зеленая
  - **Просрочено** — дата  обучения выходит за пределы актуального периода - желтая.

В таблице можно редактировать только "Потребность в обучении" по каждой программе (двойной клик переключает "Да"/"Нет"). Полное редактирование ФИО, СНИЛС, должности и списка программ — через контекстное меню → "Редактировать" (открывает диалог).



**Статусы обучения по периодам:**
- Для программ 1-29 (кроме 5): статус "Обучен" если дата обучения <= 3 года от текущей даты
- Если потребность в обучении есть, но дата обучения отсутствует или результат "Неудовлетворительно" — статус "Не обучен"
- Если дата обучения выходит за 3 года — статус "Просрочено"

**2.7.3. Запрос данных из реестра Минтруда по СНИЛС**
- Кнопка "Запросить из реестра" — для выбранного сотрудника (или для всех) отправляет запрос `query_by_snils` к API Минтруда

**2.7.5 Формирование программ обучения**

1. **Кнопка "Сформировать план обучения на текущий год"**

#### Назначение

Автоматически формирует список сотрудников, которых нужно обучить/переобучить в текущем году.

Критерии:

- есть потребность = 1
- статус:
  - Не обучен
  - Просрочено
  - Истекает в текущем году (опционально)

------

#### Алгоритм

Для каждого сотрудника:

для каждой программы:

##### 1. Если need_training = 0

пропуск.

------

##### 2. Если нет даты обучения

добавить в план:

- причина = "Не обучен"
- срок обучения - текущая дата + 60 календарных дней

------

##### 3. Если result = неудовлетворительно

добавить:

- причина = "Не сдал"

------

##### 4. Если дата > 3 лет

добавить:

- причина = "Просрочено"

```
expiry_date = exam_date + relativedelta(years=3)
```

------

##### 5. Если дата истекает в текущем году

(например 2026)

если:

```
expiry_date.year == current_year
```

добавить:

- причина = "Истекает в текущем году"

Это позволит планировать заранее.

------

##### Структура результата

Таблица:

- №
- ФИО
- СНИЛС
- Должность
- Программа
- Причина включения
- Последняя дата обучения
- Дата окончания действия
- Приоритет

------

##### Приоритеты

###### Высокий

- Не обучен
- Не сдал

------

###### Средний

- Просрочено

------

###### Низкий

- Истекает в текущем году

------

Пример:

| ФИО          | Программа | Причина             | Приоритет |
| ------------ | --------- | ------------------- | --------- |
| Иванов И.И.  | 1         | Не обучен           | High      |

## Кнопка "Сформировать план на следующий год"

**Назначение:**
 Автоматическое формирование перечня работников, подлежащих обучению или переобучению в следующем календарном году на основании потребности в обучении и сроков действия ранее пройденного обучения.

Источник данных: раздел **Сводка по сотрудникам** (локальная БД сотрудников и результаты запросов из реестра Минтруда).

------

## Логика формирования

Пусть:

- текущий год = `current_year`
- планируемый = `plan_year = current_year + 1`

Например:

- сейчас 2026 → формируется план на 2027.

------

### В план включаются сотрудники, если:

##### 1. Требуется обучение, но обучение отсутствует

Условия:

- `need_training = 1`
- дата обучения отсутствует

Результат:

- включить в план
- срок обучения - текущая дата + 60 календарных дней

Причина:

- **Не обучен**

Приоритет:

- Высокий

------

##### 2. Последняя попытка неуспешна

Условия:

- `need_training = 1`
- последняя запись `result = false` / "Неудовлетворительно"

Результат:

- включить в план
- срок обучения - текущая дата + 30 календарных дней

Причина:

- **Не сдал проверку знаний**

Приоритет:

- Высокий

------

##### 3. Срок действия заканчивается в следующем году

Для программ:

- 1–29 (кроме 5)

Формула:

```
expiry_date = exam_date + 3 years
```

Условие:

```
expiry_date.year == plan_year
```

Результат:

- включить в план

Причина:

- **Истекает срок действия**

Приоритет:

- Средний

------

##### 4. Обучение уже просрочено на момент формирования

Условие:

```
expiry_date < today
```

Результат:

- включить в план
- срок обучения - текущая дата + 30 календарных дней

Причина:

- **Просрочено**

Приоритет:

- Высокий

------

##### Не включаются в план

Если:

- `need_training = 0`

или

- срок действия обучения истекает позже следующего года.

### 3.4. Шифрование и безопасность

**Принцип:** SQLite-БД — обычная (без файлового шифрования). Персональные данные защищены на уровне отдельных полей (ФИО, СНИЛС). Конфиденциальные настройки шифруются целиком.

#### Что шифруется

| Данные | Метод | Файл |
|--------|-------|------|
| SQLite-БД (ФИО, СНИЛС, программы, журнал) | Полевое шифрование (Fernet) | `app_data.db` |
| API-ключ Минтруда | Fernet | `api_key.json` |
| Настройки УЦ и Заказчика | Fernet | `org_settings.json` |
| Данные комиссии | Fernet | `commission_data.json` |
| Пароль прокси | Fernet | `proxy_settings.json` |
| Мастер-ключ | DPAPI (CryptProtectData) / raw fallback | `master.key` |

#### Ключ шифрования (Мастер-ключ)

- **Основной режим:** мастер-ключ генерируется случайно (32 байта) и защищается Windows DPAPI (привязка к учётной записи + машине)
- **Fallback:** если DPAPI недоступен, мастер-ключ сохраняется в открытом виде с предупреждением в логе

#### Жизненный цикл БД

1. **Запуск приложения**: SQLite открывается напрямую (WAL-журналирование)
2. **Работа**: чтение/запись зашифрованных полей через Fernet-ключ
3. **Поиск по СНИЛС**: через хеш-поле `snils_hash` (SHA256) — сам СНИЛС остаётся зашифрованным
4. **Бэкап**: копия `app_data.db` через shutil.copy2 — данные уже зашифрованы
5. **Закрытие**: обычное закрытие SQLite-соединения (повторного шифрования не требуется)

#### Логирование

Все логи фильтруются через `SensitiveDataFilter`:
- СНИЛС: маскируются (`123-456-789 00` → `***-***-*** **`, `12345678900` → `***********`)
- Пароли: заменяются на `***`
- API-ключи: заменяются на `***`
- URL с credentials: заменяются на `https://***:***@***`
- Прокси URL заменяются на `https://***`

<EducatedPersonFilter>
