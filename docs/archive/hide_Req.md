# Требования к системе Норма ОТ: Реестр обучения.

## Назначение
Система предназначена для генерации XML файлов с данными работников, обученных требованиям охраны труда согласно 2464 в целях автоматизации внесения информации о работниках в базу данных Минтруда по API и генерации протоколов проверки знаний с целью оптимизации времени работы специалистов по охране труда.

## Границы системы
*(пусто)*

## Глоссарий
- **Система** - разрабатываемое ПО (десктопное приложение )
- **Вкладка** - отдельная страница/панель в главном окне приложения (`UserControl`)
- **Учебный центр** - организация, проводящее обучение
- **Заказчик** - организация, в которой числится работник (работодатель)
- **XSD файл** - схема создания XML документа, соответствующая требованиям Минтруда, с сайта https://akot.rosmintrud.ru/sout/info
- **сайт Минтруда** - https://lkot.mintrud.gov.ru/ , раздел Обучение по охране труда.
- **Приоритеты**: Must have (M), Should have (S), Could have (C), Won't have (W)
- **SetId** - уникальный идентификатор загрузки данных в систему Минтруда, возвращается сервером после успешной отправки XML. Используется для последующего запроса регистрационных номеров
- **Регистрационный номер (InternalExamination)** - уникальный номер записи о прохождении проверки знаний работником в реестре Минтруда, присваивается автоматически после обработки данных

## Функциональные требования

### Загрузка данных (M)

**FR-001**: система должна поддерживать ручной ввод данных о работнике на вкладке "Внесение данных". (M) **Описание**: Пользователь заполняет форму работника вручную и сохраняет запись в системе. **Обоснование**: Позволяет завести запись без файлообмена. **Критерии приемки**:

- AC-1: Есть поля для внесения данных: Фамилия, Имя, Отчество, Должность, СНИЛС, Номер программы, Номер протокола, Результат, Дата.
- AC-2: При корректно заполненных полях запись создаётся, статус «Запись создана».
- AC-3: При незаполненных обязательных полях система подсвечивает ошибки и не сохраняет.
- AC-4: Валидация Фамилия, Имя, Отчество, Должность - только текст. При неправильном вводе - сообщение об ошибке ввода.
- AC-5: Валидация СНИЛС - 11 цифр. Имеется возможность вставить данные из буфера обмена. При вводе вручную СНИЛС автоматически форматируется в вид "123-456-789 00" (расстановка "-" и " " при наборе цифр). При загрузке из Excel/XML СНИЛС также приводится к формату "123-456-789 00" независимо от исходного написания. При неправильном вводе - сообщение об ошибке после нажатия кнопки "Сохранить данные".
- AC-6: Валидация Номер программы: числа от 1 до 29, за исключением 5. Знак ",". Поддерживается запись в виде "1,2" и "1,2,". При неправильном вводе - сообщение об ошибке ввода после нажатия кнопки "Сохранить данные".
- AC-7: Валидация Результат - только "Удовлетворительно" и "Неудовлетворительно". Формат поля - выпадающий список. По умолчанию выбрано "Удовлетворительно".
- AC-8: при наличии в строке Номер программы более одной программы, разделенных запятыми, в систему вносится столько строк, сколько выбрано программ. Данные работника, УЦ, Работодателя повторяются во всех строках, уникальны номера программ. При дублировании - наличия строки с аналогичным СНИЛС и Номером программы - отображение ошибки с текстом "Выявлены аналогичные данные - х строк". Проверка дублей выполняется при ручном вводе и при импорте файлов.
- AC-9: при нажатии кнопку "Сохранить данные" в разделе "Ручной ввод" данные строк вносятся в память программы (`ObservableCollection<WorkerViewModel>`) и отображаются во вкладке "Просмотр данных". В случае отсутствия данных в строках появляется ошибка "Заполните все строки". После внесения данных все поля, кроме "№ программы", очищаются.
- AC-10: при нажатии на кнопку "Очистить" в разделе "Ручной ввод" данные всех строк очищаются.
- AC-11: валидация Дата - дата меньше или равна текущей даты, формат ввода в ячейку ЧЧ.ММ.ГГГГ или ЧЧММГГГГ. В случае ошибки ввода - сообщение "Дата некорректна. Ведите корректную дату в формате ЧЧ.ММ.ГГГГ или ЧЧММГГГГ". При загрузке из Excel поддерживаются даты в формате datetime и Excel serial date (конвертация через `DateTime.FromOADate()`).

**FR-002**: система должна поддерживать ручной ввод данных об Учебном центре и Заказчике на вкладке "Внесение данных". (M) **Описание**: Пользователь вносит данные об учебном центре и работодателе вручную (ИНН и Название), и сохраняет запись в системе при нажатии на кнопку "Сохранить данные", расположенную под полями ввода. **Обоснование**: Позволяет внести обязательные данные для конвертации согласно схемы XSD. **Критерии приемки**:

- AC-1: Имеются строки для внесения цифр : ИНН УЦ, ИНН Заказчика.
- AC-2: имеются строки для ввода текста: Название УЦ, Название Заказчика.
- AC-3: в строки возможно вставить данные из буфера обмена.
- AC-4: внесенные данные сохраняются между сессиями.
- AC-5: валидация ИНН - 10 или 12 цифр. В случае некорректного внесения - сообщение об ошибке "ИНН - только 10 или 12 цифр".
- AC-6: в случае отсутствия данных в полях при нажатии кнопку "Сохранить данные" в разделе "Ручной ввод" появляется ошибка "Заполните данные УЦ/Работодателя". При нажатии кнопки "Сохранить данные" введенная информация в полях сохраняется согласно FR-009.

**FR-003**: система должна предоставлять данные об имеющихся программах обучения на вкладке "Внесение данных".(M) **Описание**: При нажатии на кнопку "Справка", расположенную возле строки "Номер программы" раздела ручного ввода, открывается перечень программ (№№1-26, без №5). При двойном клике на программу ее номер вносится в строку "Номер программы" **Обоснование**: Позволяет внести обязательные данные путем их выбора для удобства пользователя **Критерии приемки**:

- AC-1: возле строки "Номер программы" раздела ручного ввода имеется кнопка "Справка", при нажатии на которую отображается перечень номеров и наименований программ обучения.
- AC-2: при выборе программы двойным кликом ее номер вносится в строку "Номер программы" с автоматическим добавлением "," в конце.
- AC-3: возможно выбрать от одной до десяти программ обучения. При большем количестве - уведомление "Превышено количество программ для одного работника".

**FR-004**: система должна поддерживать загрузку XLSX (xls) файлов с данными работников на вкладке "Внесение данных".(M) **Описание**: Пользователь выбирает XLSX(xls) , система валидирует и создаёт/обновляет записи в программе. **Обоснование**: Массовый импорт ускоряет первичное наполнение. **Критерии приемки**:

- AC-1: Успешный импорт корректного файла создаёт записи согласно шаблону. Поддерживаются форматы .xlsx и .xls (через `ClosedXML` или `ExcelDataReader`).
- AC-2: Для строк с ошибками формируется отчёт. После загрузки появляется информационное окно с текстом "Количество строк с ошибками: Х" и кнопкой "Показать ошибки". При нажатии кнопки пользователь может сохранить XLSX-файл с детализацией ошибок. Файл содержит: тип ошибки, номер строки, поле, описание ошибки. Номера строк с ошибками указаны в колонке "Номер строки". Также в файл включаются дубликаты с указанием аналогичных строк.
- AC-3: Логирование ошибок импорта
- AC-4: в случае успешного импорта - сообщение "Успешно загружено."
- AC-5: в случае ошибки - сообщение "Ошибка импорта"
- AC-6: поддерживаемый шаблон XLSX(xls) должен содержать следующие столбцы: Фамилия, Имя, Отчество, СНИЛС, Должность, ИНН Заказчика, Наименование ЮЛ Заказчика, ИНН УЦ, Наименование УЦ, Результат,№ программы, Дата, № протокола. Поля ИНН Заказчика, Наименование ЮЛ Заказчика, ИНН УЦ, Наименование УЦ являются необязательными. При отсутствии данных в этих полях подставляются значения, введённые на вкладке "Внесение данных" в разделе "Данные УЦ и работодателя".

**FR-005**: система должна поддерживать загрузку XML файлов с данными работников на вкладке "Внесение данных".(M) **Описание**: Импорт XML по XSD-схеме, валидация и создание/обновление записей. **Обоснование**: Массовый импорт ускоряет первичное наполнение. **Критерии приемки**:

- AC-1: Файл, соответствующий XSD, импортируется без ошибок.
- AC-2: При несоответствии XSD отображается список нарушений.
- AC-3: Логирование ошибок импорта
- AC-4: в случае успешного импорта - сообщение "Успешно загружено."
- AC-5: в случае ошибки - сообщение "Ошибка импорта"

**FR-006**: система должна поддерживать загрузку XSD файла на вкладке "Внесение данных".(M) **Описание**: Импорт XSD-схемы для валидации и создания/обновления записей. **Обоснование**: Создаваемые XML файлы должны соответствовать предоставляемой XSD, файл XSD может меняться **Критерии приемки**:

- AC-1: Файл XSD импортируется без ошибок.
- AC-2: загружаемые XML файлы валидируются по загруженному XSD (`System.Xml.Schema.XmlReaderSettings`)
- AC-3: Логгирование ошибок импорта
- AC-4: загруженная схема XSD сохраняется в файлах приложения.
- AC-5: в случае успешного импорта - сообщение "Успешно загружено."
- AC-6: в случае ошибки - сообщение "Ошибка импорта" и генерация отчета согласно FR-037.
- AC-7: сохраненная схема размещается в подразделе "data" корневой директории программы.

**FR-007**: система должна направлять на сайт Минтруда с актуальной схемой XSD. (M) **Описание**: при нажатии на кнопку "Схема XSD" система открывает браузер со ссылкой "https://akot.rosmintrud.ru/sout/info" **Обоснование**: при необходимости обновления схемы XSD в случае ее изменения. **Критерии приемки**:

- AC-1: при нажатии на кнопку "Схема XSD" открывается системный браузер со ссылкой "https://akot.rosmintrud.ru/sout/info" (`Process.Start(new ProcessStartInfo { FileName = url, UseShellExecute = true })`)

**FR-008**: система должна формировать шаблон xlsx файла для заполнения. (M) **Описание**: при нажатии на кнопку "Создать шаблон" система генерирует xlsx файл в корневом хранилище приложения. **Обоснование**: формирование шаблона, поддерживаемого программой **Критерии приемки**:

- AC-1: при нажатии на кнопку "Создать шаблон" система генерирует xlsx файл с именем "Шаблон.xlsx" со столбцами: Фамилия, Имя, Отчество, СНИЛС, Должность, ИНН Заказчика, Наименование ЮЛ Заказчика, ИНН УЦ, Наименование УЦ, Результат,№ программы, Дата, № протокола.
- AC-2: после создания файла система уведомляет пользователя окном уведомления "Шаблон создан. Открыть расположение файла?". В случае нажатия кнопки Открыть - открывается расположение файла (корневая папка программы), в случае нажатия кнопки Отмена - диалоговое окно закрывается.

**FR-009**: Сохранение данных УЦ и Заказчика в JSON **Описание**: Данные об Учебном центре и Заказчике должны сохраняться между сессиями в файле формата JSON, расположенном в директории `/data/` приложения. **Обоснование**: Переносимость настроек, возможность ручного редактирования, прозрачность хранения. **Критерии приемки**:

- AC-1: При запуске приложения данные об УЦ и Заказчике загружаются из файла `/data/org_settings.json` (`System.Text.Json`)
- AC-2: При нажатии кнопки "Сохранить данные" информация об УЦ и Заказчике сохраняется в файл `/data/org_settings.json`

### Отображение данных (M)

**FR-010**: система должна формировать на вкладке "Просмотр данных" перечень работников согласно внесенных данных из нескольких файлов различного типа и вручную. (M) **Критерии приемки**:

- AC-1: в систему загружаются данные из файлов xlsx, xml, данные отображаются корректно
- AC-2: при загрузке второго и далее файлов появляется диалоговое окно "что делать с данными" с кнопками "объединить, удалить старые, отменить загрузку".
- AC-3: при объединении данных добавляются строки работников с уникальными СНИЛС и номерами программ. Дубликаты пропускаются. Приоритет имеют уже существующие в системе данные.
- AC-4: на вкладке "Просмотр данных" присутствует `DataGrid` со столбцами: Фамилия, Имя, Отчество, СНИЛС, Должность, ИНН Заказчика, Наименование ЮЛ заказчика, ИНН УЦ, Наименование УЦ, Результат, № программы, Дата, № протокола.
- AC-5: При нажатии на кнопку "Очистить" появляется диалоговое окно подтверждения.

**FR-011**: система должна отображать введенные данные на вкладке "Просмотр данных". (M) **Критерии приемки**:

- AC-1: загруженные данные отображаются на вкладке "Просмотр данных"
- AC-2: для работника, обученного по N программ, должно отображаться N строк с уникальными номерами программ

### Конвертация (M)

**FR-018**: система должна конвертировать данные в формат XML в соответствии с приложенным XSD файлом. (M) **Критерии приемки**:

- AC-1: при нажатии кнопки "Конвертация" предлагается выбрать место размещения и имя создаваемого файла (`SaveFileDialog`)
- AC-2: проводится конвертация данных в соответствие со схемой XSD, размещенной в папке "data". Формат XML: корневой элемент `RegistrySet`, каждый `RegistryRecord` (maxOccurs=5000) содержит `Worker`, `Organization` (УЦ), `Test` (с атрибутами `isPassed`, `learnProgramId`). Группировка по протоколу НЕ выполняется. Дата в формате `xs:date` (YYYY-MM-DD). `isPassed = "true"` для "Удовлетворительно", `"false"` для "Неудовлетворительно".
- AC-3: созданный файл принимается информационной системой Минтруда
- AC-4: в случае отсутствия XSD появляется уведомление "XSD отсутствует"
- AC-5: XML формируется в кодировке UTF-8
- AC-6: СНИЛС сохраняется в виде "123-456-789 00"
- AC-7: при отправке на сервер Минтруда формируется `multipart/form-data` запрос с двумя файлами: `Request.xml` и `Data.olot` (ZIP с `Data.xml`). Отправка POST-методом на `https://edu.rosmintrud.ru/api/set/push`
