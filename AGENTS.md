# Excel-XML для Минтруда

Wails (Go) desktop app для генерации XML файлов с данными работников, обученных требованиям охраны труда согласно 2464 в целях автоматизации внесения информации о работниках в базу данных Минтруда и генерации протоколов проверки знаний с целью оптимизации времени работы специалистов по охране труда.

## Architecture
- Программа должна работать из одного файла, поддерживать настройки proxy как системный браузер

## Build Requirements
- **Single executable**: Приложение собирается в один `.exe` файл (без внешних зависимостей)
- **No console window**: После сборки приложение не имеет cmd-окна (параметр `-ldflags "-H=windowsgui"` или настройка wails.json)
- **Data directory**: Все пользовательские данные (org_settings.json, api_key.json, proxy_settings.json, exam_journal.json, workers.json) сохраняются в папке `data/` рядом с исполняемым файлом
- **Schema directory**: XSD-схемы сохраняются в папке `schema/` рядом с исполняемым файлом
- **Templates directory**: Шаблоны протоколов (Protokol.docx) хранятся в папке `templates/` рядом с исполняемым файлом
- **Logs directory**: Логи ошибок сохраняются в папке `logs/` рядом с исполняемым файлом
- Порядок разработки в ``` ROADMAP.md```

## Important Quirks
- "Ручной ввод данных работника" расположение полей ввода - в 2 столбца 
- SNILS format auto-formatted on save
- Workers grouped by SNILS when generating XML
- Journal tracks SetId for API responses

## Data Flow
1. Load XLSX/JSON → Workers array
2. Add/edit workers → ValidateWorker → Save to JSON
3. Generate XML → Group by SNILS → Single EducatedPerson per SNILS
4. Send to API → Journal entry created
5. Query by SetId/SNILS → Update Journal status

### Загрузка данных (M)

1. **FR-001**: система должна поддерживать ручной ввод данных о работнике на вкладке "Внесение данных". (M)
   Описание: Пользователь заполняет форму работника вручную и сохраняет запись в системе.
   Обоснование: Позволяет завести запись без файлообмена.
   Критерии приемки:
   - AC-1: Есть поля для внесения данных: Фамилия, Имя, Отчество, Должность, СНИЛС, Номер программы, Номер протокола, Результат, Дата.
   - AC-2: При корректно заполненных полях запись создаётся, статус «Запись создана».
   - AC-3: При незаполненных обязательных полях система подсвечивает ошибки и не сохраняет.
   - AC-4: Валидация Фамилия, Имя, Отчество, Должность - только текст. При неправильном вводе - сообщение об ошибке ввода.
   - AC-5: Валидация СНИЛС - 11 цифр. Имеется возможность вставить данные из буфера обмена. При вводе вручную СНИЛС автоматически форматируется в вид "123-456-789 00" (расстановка "-" и " " при наборе цифр). При загрузке из Excel/XML СНИЛС также приводится к формату "123-456-789 00" независимо от исходного написания. При неправильном вводе - сообщение об ошибке после нажатия кнопки "Сохранить данные".
   - AC-6: Валидация Номер программы: числа от 1 до 29, за исключением 5. Знак ",".  Поддерживается запись в виде "1,2" и "1,2,". При неправильном вводе - сообщение об ошибке ввода после нажатия кнопки "Сохранить данные".
   - AC-7: Валидация Результат - только "Удовлетворительно" и "Неудовлетворительно". Формат поля - выпадающий список. По умолчанию выбрано "Удовлетворительно".
   - AC-8: при наличии в строке Номер программы более одной программы, разделенных запятыми, в систему вносится столько строк, сколько выбрано программ. Данные работника, УЦ, Работодателя повторяются во всех строках, уникальны номера программ. При дублировании - наличия строки с аналогичным СНИЛС и Номером программы - отображение ошибки с текстом "Выявлены аналогичные данные - х строк". Проверка дублей выполняется при ручном вводе и при импорте файлов.
   - AC-9: при нажатии кнопку "Сохранить данные" в разделе "Ручной ввод" данные строк вносятся в память программы и отображаются во вкладке "Просмотр данных". В случае отсутствия данных в строках появляется ошибка "Заполните все строки". После внесения данных все поля, кроме "№ программы", очищаются.
   - AC-10: при нажатии на кнопку "Очистить" в разделе "Ручной ввод" данные всех строк очищаются.
   - AC-11: валидация Дата - дата меньше или равна текущей даты, формат ввода в ячейку ЧЧ.ММ.ГГГГ или ЧЧММГГГГ. В случае ошибки ввода - сообщение "Дата некорректна. Ведите корректную дату в формате ЧЧ.ММ.ГГГГ или ЧЧММГГГГ". При загрузке из Excel поддерживаются даты в формате datetime и Excel serial date.

## FR-009: Сохранение данных УЦ и Заказчика в JSON

**Описание**: Данные об Учебном центре и Заказчике должны сохраняться между сессиями в файле формата JSON, расположенном в директории `/data/` приложения, вместо использования системного реестра или QSettings.

**Обоснование**:

- Переносимость настроек между разными системами
- Возможность ручного редактирования конфигурации
- Прозрачность хранения данных
- Упрощение резервного копирования и миграции

**Критерии приемки**:

- AC-1: При запуске приложения данные об УЦ и Заказчике загружаются из файла `/data/org_settings.json`
- AC-2: При нажатии кнопки "Сохранить данные" информация об УЦ и Заказчике сохраняется в файл `/data/org_settings.json`
- AC-3: Файл имеет формат JSON с полями: `tc_inn`, `tc_title`, `employer_inn`, `employer_title`
- AC-4: При отсутствии файла создается новый с пустыми значениями
- AC-5: При ошибке чтения/записи файла пользователю отображается предупреждение

**Пример структуры JSON**:

```json
{
    "tc_inn": "1234567890",
    "tc_title": "Учебный центр \"Профессионал\"",
    "employer_inn": "0987654321",
    "employer_title": "ООО \"Работодатель\""
}
```

18. **FR-023**: Система должна поддерживать настройку подключения через прокси-сервер. (M)
       Описание: На вкладке "Передача данных" имеется раздел "Настройки прокси" с тремя режимами работы: "Без прокси" (прямое подключение), "Авто (системные)" (использование прокси из настроек Windows), "Вручную" (ручной ввод адреса, логина и пароля прокси).
       Обоснование: Корпоративные сети часто требуют аутентификации на прокси-сервере для доступа к интернет-ресурсам. Система должна корректно работать с прокси, включая HTTPS CONNECT туннели.
       Критерии приемки:
    - AC-1: На вкладке "Передача данных" имеется раздел "Настройки прокси" с тремя радиокнопками: "Без прокси", "Авто (системные)", "Вручную".
    - AC-2: В режиме "Вручную" отображаются поля: "Адрес прокси" (формат http://proxy.example.com:3128), "Логин", "Пароль".
    - AC-3: В режиме "Авто (системные)" система автоматически определяет прокси из реестра Windows (HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings).
    - AC-4: При нажатии кнопки "Сохранить настройки" данные сохраняются в файл `/data/proxy_settings.json` в формате JSON с полями: mode, url, username_encrypted, password_encrypted. Логин и пароль шифруются алгоритмом Fernet (AES) с ключом, производным от имени пользователя системы.
    - AC-5: При нажатии кнопки "Тест подключения" система проверяет доступность сервера Минтруда (https://edu.rosmintrud.ru) через указанные настройки и отображает результат.
    - AC-6: Для HTTPS-соединений (CONNECT туннель) аутентификация на прокси выполняется путем встраивания credentials в URL прокси (`http://user:pass@proxy:port`), а не через заголовки `Proxy-Authorization`. Это обеспечивает корректную работу с корпоративными прокси, требующими авторизацию.
    - AC-7: Настройки прокси используются при отправке XML (FR-020), запросе по SetId (FR-021) и запросе по СНИЛС (FR-022).
    - AC-8: Для NTLM-аутентификации (логин вида DOMAIN\login или login@domain) используется библиотека requests-ntlm, которая автоматически выбирается при наличии обратного слеша в логине.
    - AC-9: В настройках прокси имеется чекбокс "TLS верификация" для включения/отключения проверки SSL-сертификатов. По умолчанию выключено для работы через корпоративный прокси с SSL-инспекцией. Включение требуется для безопасного соединения.
    - AC-10: Пароль прокси скрыт (показывается только при зажатии кнопки). Аналогично скрывается API-ключ.

19. **FR-024**: Система должна предоставлять альтернативный механизм передачи данных с использованием urllib. (M)
      Описание: В приложении имеется дополнительная вкладка "Передача данных (urllib)", дублирующая функционал вкладки "Передача данных", но использующая библиотеку urllib вместо requests для HTTP-запросов. Это обеспечивает резервный механизм подключения к серверу Минтруда при проблемах с прокси-серверами в корпоративной сети.
      Обоснование: Библиотека requests не всегда корректно работает с некоторыми корпоративными прокси-серверами, особенно при HTTPS CONNECT туннелях с аутентификацией. Urllib имеет более низкоуровневый доступ к настройкам прокси и может решать проблемы, где requests не справляется.
      Критерии приемки:

   - AC-1: В приложении имеется вкладка "Передача данных (urllib)", расположенная после вкладки "Передача данных".
   - AC-2: Вкладка "Передача данных (urllib)" содержит все разделы основной вкладки: API ключ, Настройки прокси, Отправка XML, Запрос по SetId, Запрос по СНИЛС.
   - AC-3: Вкладка использует модуль `api/mintrud_api_urllib.py` с функциями `push_xml()`, `get_by_set_id()`, `get_by_snils()`, реализованными на базе urllib.request.
   - AC-4: Для работы с прокси используются `ProxyHandler` и `HTTPBasicAuthHandler` из urllib, обеспечивающие корректную аутентификацию на корпоративных прокси.
   - AC-5: Настройки прокси (режим, адрес, логин, пароль) общие для обеих вкладок и хранятся в `/data/proxy_settings.json`.
   - AC-6: API ключ общий для обеих вкладок и хранится в `/data/api_key.json`.
   - AC-7: Вкладка "Передача данных (urllib)" подключена к журналу проверки знаний — записи добавляются и обновляются аналогично основной вкладке.

### Журнал проверки знаний (M)

      Обоснование: Пользователь теряет SetId после закрытия диалога. Журнал позволяет отслеживать историю отправок, связывать SetId с конкретными работниками и автоматически подтягивать регистрационные номера.

      Обоснование: Возможность печати, архивирования и отправки отчёта.
      Критерии  приемки:

   - AC-1: При нажатии «Экспорт в XLSX» открывается диалог сохранения файла.
   - AC-2: Экспортируемый файл содержит все видимые (отфильтрованные) записи.
   - AC-3: Столбцы XLSX: Дата отправки, SetId, Фамилия, Имя, Отчество, СНИЛС, Должность, № программы, Название программы, Дата экзамена, № протокола, Регистрационный номер, Статус.
   - AC-4: Заголовки стилизованы (жирный шрифт, цветной фон).
   - AC-5: Автоподбор ширины столбцов.

25. **FR-030**: Система должна удалять записи из журнала. (M)
      Описание: Пользователь может удалить выбранные записи из журнала через контекстное меню или кнопку «Удалить».
      Обоснование: Очистка журнала от ненужных/ошибочных записей.
      Критерии  приемки:

   - AC-1: Правый клик по строке → контекстное меню → «Удалить».
   - AC-2: При удалении появляется подтверждение «Удалить выбранную запис(ь/и)? Данные удалятся безвозвратно.»
   - AC-3: После подтверждения записи удаляются из таблицы и из `/data/exam_journal.json`.

### Печать протокола (S)

26. **FR-031**: Система должнаформировать протокол проверки знаний на основе данных журнала. (S)

       Критерии  приемки:
    - AC-1: Кнопка «Печать протокола» на вкладке «Журнал проверки знаний».
    - AC-2: При нажатии открывается диалог выбора номера протокола: выбор из списка доступных номеров или опция «Все».
    - AC-3: При выборе одного протокола — сохраняется в файл с именем «Протокол {номер} от {дата}.docx».
    - AC-4: При выборе «Все» — открывается диалог выбора папки, каждый протокол сохраняется в отдельный файл.
    - AC-5: Система заполняет шаблон `Protokol_proverki_znanii_OT.docx` данными: ФИО, СНИЛС, Должность, № программы, Результат, Дата, № протокола.
    - AC-6: Результат всегда «Удовлетворительно».
    - AC-7: Файл сохраняется в выбранную пользователем директорию.
    - AC-8: Путь сохранения запоминается для следующих операций.
    - AC-9: Дата проверки знаний автоматически подставляется из данных журнала.
    - AC-10: Шрифт документа — Times New Roman.

## Формирование протокола (S)

27. **FR-032**: Система должна формировать протокол проверки знаний на вкладке «Протокол» с автозаполнением даты. (S)
       Описание: На вкладке «Протокол» пользователь выбирает номер протокола из выпадающего списка (или «Все»), автоматически заполняется дата проверки знаний из журнала.
       Обоснование: Упрощает формирование протокола, автоматизирует заполнение даты.
       Критерии приемки:
       - AC-1: Вкладка «Протокол» содержит выпадающий список номеров протоколов из журнала + опцию «Все».
       - AC-2: При выборе номера протокола автоматически заполняется поле «Дата проверки знаний» из данных журнала.
       - AC-3: Один протокол: имя файла «Протокол {номер} от {дата}.docx».
       - AC-4: При выборе «Все»: открывается диалог выбора папки, каждый протокол сохраняется в отдельный файл.
       - AC-5: Шрифт документа — Times New Roman.
       - AC-6: Результат проверки знаний всегда «Удовлетворительно».

28. **FR-033**: Система должна поддерживать импорт данных из Excel файла в журнал проверки знаний. (S)
       Описание: Пользователь может импортировать записи из Excel файла, соответствующего формату экспорта журнала, для восстановления или добавления данных в журнал проверки знаний.
       Обоснование: Позволяет восстановить журнал из резервной копии или импортировать данные из внешних источников.
       Критерии приемки:
       - AC-1: На вкладке «Журнал проверки знаний» имеется кнопка «Импорт из Excel».
       - AC-2: При нажатии кнопки открывается диалог выбора Excel файла (.xlsx, .xls).
       - AC-3: Система проверяет соответствие структуры файла ожидаемому формату (обязательные колонки: Фамилия, Имя, Отчество, СНИЛС, Должность, № программы, Дата экзамена, № протокола).
       - AC-4: При успешном импорте записи добавляются в журнал с сохранением всех данных (SetId, дата отправки, XML файл, регистрационный номер, статус).
       - AC-5: При обнаружении ошибок в данных система выводит предупреждение с детализацией problematic rows, но продолжает импорт корректных записей.
       - AC-6: После импорта система уведомляет пользователя о количестве успешно импортированных записей.

29. **FR-034**: Система должна поддерживать создание шаблона журнала проверки знаний. (S)
       Описание: Пользователь может сгенерировать шаблон Excel файла журнала проверки знаний с одной тестовой записью для последующего заполнения и импорта.
       Обоснование: Упрощает процесс начальной настройки и предоставляет пример правильного формата данных.
       Критерии приемки:
       - AC-1: На вкладке «Журнал проверки знаний» имеется кнопка «Сформировать шаблон журнала».
       - AC-2: При нажатии кнопки открывается диалог выбора места сохранения Excel файла.
       - AC-3: Сгенерированный файл содержит правильные заголовки колонок журнала.
       - AC-4: Сгенерированный файл содержит одну тестовую запись с заполненными примерами данных.
       - AC-5: Тестовая запись содержит корректно formatted СНИЛС и реалистичные значения для всех полей.

30. **FR-035**: Система должна поддерживать фильтрацию по номеру протокола в журнале. (S)
       Описание: На вкладке «Журнал проверки знаний» добавлен фильтр по номеру протокола.
       Критерии приемки:
       - AC-1: Выпадающий список на панели фильтров с опцией «Все» и списком уникальных номеров протоколов.
       - AC-2: При выборе номера протокола таблица фильтруется только по выбранному протоколу.

31. **FR-036**: Система должна запоминать последний путь сохранения файлов. (S)
       Описание: При сохранении протоколов и экспорте журнала путь сохраняется для следующих операций.
       Критерии приемки:
       - AC-1: Путь сохраняется в файл настроек (journal_settings.json, protocol_settings.json).
       - AC-2: При следующем сохранении предлагается последний использованный путь.
       - AC-3: Путь обновляется после каждого успешного сохранения.

### BR-PROTOCOL-002: Формирование объема проверки знаний (ячейки B20-B24)

**Описание:** Формирование текста программ обучения для протокола

**Алгоритм:**

1. Для каждого работника, попавшего в протокол (по номеру протокола), взять номера программ из столбца "№ программы" таблицы "Просмотр".

2. Для каждого номера программы взять данные из таблицы "Программы обучения" (Номер документа, Часы, Название).

3. Сформировать текст программы в виде:  {{длительность программы обучения №}}{{номер программы обучения №}} «{{название программы обучения №}}».

   {{длительность программы обучения №}} - формируется как Значение "Часы" таблицы "Программы обучения" + текст "-часовой программе обучения".

4. Программы вносятся в форму протокола

5. Для совпадающих ФИО — регистрационные номера программ объединяются в одну ячейку таблицы\

6. Для каждого следующего работника, имеющего тот же номер протокола, создается новая строка в таблице .

### Конвертация (M)

13. **FR-018**: система должна конвертировать данные в формат XML в соответствии с приложенным XSD файлом. (M)
      Описание: При нажатии кнопки "Конвертация" на вкладке "Просмотр данных"  система должна конвертировать имеющиеся данные в формат XML в соответствии с загруженным XSD файлом.
      Обоснование: сайтом Минтруда поддерживается загрузка XML файла, соответствующего XSD схеме.
      Критерии  приемки:

   - AC-1: при нажатии кнопки кнопки "Конвертация" на вкладке  "Просмотр данных" предлагается выбрать место размещения и имя создаваемого файла
   - AC-2: при нажатии кнопки проводится конвертация данных в соответствие со схемой XSD, размещенной в папке "schema". Формат XML: корневой элемент RegistrySet, каждый RegistryRecord (maxOccurs=5000) содержит Worker, Organization (УЦ), Test (с атрибутами isPassed, learnProgramId). Группировка по протоколу НЕ выполняется — каждая запись отдельна. Дата в формате xs:date (YYYY-MM-DD). isPassed = "true" для "Удовлетворительно", "false" для "Неудовлетворительно".
   - AC-3: созданный файл принимается информационной системой Минтруда (при ручной загрузке)
   - AC-4: в случае отсутствия загруженного XSD файла при нажатии кнопки появляется уведомление "XSD отсутствует"
   - AC-5: XML Должен формироваться в формате UTF-8
   - AC-6: в XML СНИЛС сохранен в виде "123-456-789 00" для отображения в программе, при отправке на сервер СНИЛС передается в этом же формате
   - AC-7: при отправке на сервер Минтруда формируется multipart/form-data запрос с двумя файлами: Request.xml (содержит ApiKey и NeedSend=false) и Data.olot (ZIP-архив с файлом Data.xml внутри, название с заглавной D). Отправка POST-методом на https://edu.rosmintrud.ru/api/set/push
