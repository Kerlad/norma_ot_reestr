# Чеклисты безопасности ИСПДн

**Проект:** Excel_to_XML
**Версия приложения:** 3.0.0
**Дата:** 21.05.2026
**Назначение:** Чеклисты для администратора и оператора ИСПДн при развёртывании, эксплуатации и реагировании на инциденты

---

## Чеклист 1: Первичное развёртывание (Deployment)

### Системные требования

- [ ] ОС Windows 10/11 Professional (для BitLocker)
- [ ] Python 3.12+ из официального источника (python.org)
- [ ] Антивирус: Microsoft Defender или Kaspersky (активен, обновлён)
- [ ] BitLocker включён на системном диске
- [ ] Windows Update — автоматические обновления
- [ ] Учётная запись с паролем (не пустой, не «1»)
- [ ] Ограничение физического доступа к ПК

### Установка приложения

- [ ] Клонирование репозитория: `git clone` или распаковка Portable
- [ ] Создание виртуального окружения: `python -m venv venv`
- [ ] Установка зависимостей: `pip install -r requirements.txt`
- [ ] Проверка версий зависимостей (pip list)
- [ ] Запуск: `python main.py` (первый запуск — создание ключей)

### Production Mode

- [ ] Установка переменной окружения:
  ```powershell
  [Environment]::SetEnvironmentVariable("EXCEL_XML_PROD", "1", "User")
  ```
- [ ] Перезапуск приложения — проверка: нет сообщения о plaintext master key
- [ ] Проверка: мастер-ключ создаётся через DPAPI (не plaintext)

### Настройка безопасности

- [ ] Установка парольной фразы (меню → Настройки → Установить парольную фразу)
- [ ] Passphrase: минимум 12 символов, буквы + цифры + спецсимволы
- [ ] Ввод API-ключа Минтруда (Внесение данных → API ключ)
- [ ] Настройка прокси (если требуется корпоративный прокси)
- [ ] Проверка подключения к API Минтруда (кнопка «Проверить подключение»)
- [ ] Настройка таймаута автоблокировки (рекомендация: 5-10 минут)
- [ ] Ввод данных организации (ИНН УЦ, Название УЦ, ИНН/Название Заказчика)
- [ ] Сохранение данных организации (кнопка «Сохранить данные»)

### Проверка после настройки

- [ ] Создание тестовой резервной копии (меню → Backup)
- [ ] Проверка: backup создан в %APPDATA%/Excel_to_XML/backups/
- [ ] Проверка: логи не содержат ПДн в открытом виде
- [ ] Проверка: HMAC integrity audit-лога (первая запись)
- [ ] Тестовый импорт XLSX с 1-2 записями
- [ ] Тестовый экспорт XML
- [ ] Проверка: ФИО в XML открыты (так и должно быть для Минтруда)

## Чеклист 2: Ежедневные операции (Daily)

- [ ] Запуск приложения
- [ ] Ввод парольной фразы (если установлена)
- [ ] Проверка: статус-карточки на Сводке сотрудников (актуальность)
- [ ] Импорт данных: проверка формата (только .xlsx)
- [ ] Верификация импорта: количество записей совпадает
- [ ] Передача XML в Минтруд (если есть новые данные)
- [ ] Получение SetId — подтверждение в ответе сервера
- [ ] SetId отобразился в поле UI и в журнале
- [ ] Запрос рег. номеров по SetId (если SetId получен)
- [ ] Проверка: статусы обновились (pending → received)
- [ ] Выход из приложения

## Чеклист 3: Еженедельные проверки (Weekly)

- [ ] Создание резервной копии БД (меню → Backup)
- [ ] Проверка: backup создан с PBKDF2-паролем от мастер-ключа
- [ ] Проверка целостности backup:
  - [ ] Копия backup на внешний носитель
  - [ ] Попытка открыть backup (восстановление на тестовой копии)
- [ ] Просмотр аудит-лога (Инструменты → Просмотр логов):
  - [ ] Нет подозрительных событий (KEY_ACCESS без контекста)
  - [ ] Нет TLS_WARNING
  - [ ] Нет XML_SECURITY_ERROR
- [ ] Проверка размера логов:
  - [ ] audit.log < 5 MB
  - [ ] app.log < 5 MB
  - [ ] error.log < 5 MB
- [ ] Синхронизация с API Минтруда:
  - [ ] Запрос статусов ожидающих SetId
  - [ ] Обновление рег. номеров
- [ ] Windows Update: проверка доступных обновлений

## Чеклист 4: Ежемесячное обслуживание (Monthly)

### Проверка безопасности

- [ ] Проверка HMAC-целостности мастер-ключа:
  - `verify_metadata_integrity()` не возвращает ошибок
  - Файл master.key.json не повреждён
- [ ] Проверка audit.log: HMAC integrity верификация записи
- [ ] Проверка файлов ключей:
  - master.key существует
  - master.key.json существует
  - passphrase_wrapped.key (если passphrase установлена)
- [ ] Проверка backup (ротация):
  - Макс. 5 копий в папке backups/
  - Старые копии удалены автоматически
  - Хотя бы один backup на внешнем носителе

### Обновление ПО

- [ ] Проверка устаревших зависимостей:
  ```powershell
  pip list --outdated
  ```
- [ ] Проверка известных уязвимостей:
  ```powershell
  pip-audit
  ```
- [ ] Обновление критических зависимостей (lxml, cryptography, requests)
- [ ] Проверка: приложение работает после обновления (запуск тестов)
- [ ] Ручное обновление из репозитория (git pull), если есть новые версии

### Анализ аудит-лога

- [ ] События KEY_ACCESS — количество и контекст
- [ ] TLS_WARNING — были ли попытки отключения TLS?
- [ ] XML_SECURITY_ERROR — попытки XXE?
- [ ] PASSPHRASE_SET / PASSPHRASE_REMOVED — были ли изменения passphrase?
- [ ] Неудачные попытки входа (PASSPHRASE — многократные)
- [ ] SELECT events: были ли массовые экспорты/чтения?

## Чеклист 5: Реагирование на инциденты (Incident Response)

### Шаг 1: Обнаружение

- [ ] Инцидент обнаружен:
  - Пользователем
  - Аудит-журналом
  - Системой мониторинга

### Шаг 2: Локализация

- [ ] Отключение рабочей станции от корпоративной сети
- [ ] Отключение Wi-Fi / Ethernet
- [ ] Завершение сессии Windows (Lock)

### Шаг 3: Сбор улик

- [ ] Копия audit.log (с HMAC-тегами)
- [ ] Копия app.log
- [ ] Копия error.log
- [ ] Копия error_response.txt (если есть)
- [ ] Копия corrupted_keys/ (если есть)
- [ ] Копия app_data.db
- [ ] Копия master.key и master.key.json
- [ ] Скриншоты интерфейса
- [ ] Snapshot содержимого working directory
- [ ] Создание forensic-копии диска (dd / FTK Imager)

### Шаг 4: Анализ

- [ ] Определение объёма утёкших данных (ФИО, СНИЛС, сколько записей)
- [ ] Определение вектора атаки:
  - [ ] Физический доступ
  - [ ] Удалённый доступ
  - [ ] Социальная инженерия
  - [ ] Программная уязвимость
- [ ] Определение времени компрометации
- [ ] Определение: были ли затронуты данные Минтруда

### Шаг 5: Уведомление

- [ ] Уведомление Роскомнадзора в течение 24 часов (предварительное)
- [ ] Уведомление Роскомнадзора в течение 72 часов (полное)
  - Форма: уведомление о факте утечки ПДн
  - Содержание: категории ПДн, количество субъектов, меры
- [ ] Уведомление субъектов ПДн (работников)
- [ ] Уведомление Минтруда (если передавались данные)
- [ ] Уведомление руководителя организации

### Шаг 6: Восстановление

- [ ] Смена мастер-ключа (KEY_ROTATION):
  - `rotate_master_key()` через приложение
  - Перешифрование всех данных
- [ ] Восстановление из последней чистой резервной копии:
  - [ ] Определение последнего backup до инцидента
  - [ ] Восстановление app_data.db
  - [ ] Восстановление master.key (из backup ключей)
- [ ] Смена API-ключа Минтруда (через личный кабинет edu.rosmintrud.ru)
- [ ] Смена парольной фразы
- [ ] Проверка целостности восстановленных данных:
  - [ ] Количество записей совпадает
  - [ ] Шифрование/расшифровка работают
  - [ ] API-ключ активен

### Шаг 7: Пост-инцидент

- [ ] Анализ коренных причин (Root Cause Analysis)
- [ ] Внесение изменений в меры защиты:
  - [ ] Если exploit — обновление кода
  - [ ] Если социальная инженерия — обучение
  - [ ] Если физический доступ — усиление контроля
- [ ] Обновление модели угроз (threat_model.md)
- [ ] Обновление реестра рисков (risk_register.md)
- [ ] Обновление политики безопасности

## Чеклист 6: Удаление данных (Data Disposal)

### Плановое удаление

- [ ] Создание резервной копии перед удалением
- [ ] Удаление через UI: контекстное меню → Удалить / кнопка «Удалить данные»
- [ ] Проверка: записи удалены из БД
- [ ] VACUUM (сжатие БД) после массового удаления

### Полное завершение эксплуатации

- [ ] Удаление app_data.db (затирание: `cipher /w:C:\путь\к\папке` или sdelete)
- [ ] Удаление master.key (secure delete)
- [ ] Удаление master.key.json
- [ ] Удаление passphrase_wrapped.key (если есть)
- [ ] Удаление backups/
- [ ] Удаление log/ (audit.log, app.log, error.log)
- [ ] Удаление secure_temp/ (если остались файлы)
- [ ] Удаление настроек: api_key.json, org_settings.json, proxy_settings.json и др.
- [ ] Составление акта уничтожения ПДн

## Приложение: Полезные команды

```powershell
# Запуск в production mode
$env:EXCEL_XML_PROD = "1"
python main.py

# Сборка EXE
Remove-Item -Recurse -Force dist\ExcelXML-Mintrud -ErrorAction SilentlyContinue
py -m PyInstaller ExcelXML-Mintrud.spec

# Запуск тестов
py -m pytest tests -v

# Проверка зависимостей
pip list --outdated
pip-audit

# Путь к данным приложения
$env:APPDATA\Excel_to_XML\

# Secure delete (Sysinternals sdelete)
sdelete.exe -p 3 путь\к\файлу.db

# PRAGMA integrity_check
sqlite3 app_data.db "PRAGMA integrity_check;"
```
