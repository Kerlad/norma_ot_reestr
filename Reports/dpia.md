# Оценка воздействия на защиту данных (ОВЗД / DPIA)

**Проект:** Excel_to_XML
**Дата:** 21.05.2026
**Версия приложения:** 3.1.0
**Версия документа:** 1.0

---

## 1. Систематическое описание операций обработки

### 1.1. Цели обработки

- Передача сведений об обучении работников по охране труда в реестр Минтруда (Постановление №2464)
- Учёт и контроль периодичности обучения сотрудников
- Формирование протоколов проверки знаний
- Сводный анализ статуса обучения

### 1.2. Тип данных

| Категория | Поля | Пример |
|-----------|------|--------|
| Прямая идентификация | ФИО, СНИЛС | Иванов Иван Иванович, 123-456-789 00 |
| Косвенная идентификация | Должность, ИНН/Название организации | Слесарь, ООО «Ромашка» |
| Иные данные | Программы, даты, протоколы, результаты | «Обучен», 01.01.2025, №П-123 |

### 1.3. Объём обработки

| Параметр | Значение |
|----------|----------|
| Максимум сотрудников | 100 000 |
| Максимум записей в БД | 5000 (workers_data) / 100 000 (employees) |
| Максимум программ | 29 (1-29, кроме 5) |
| Средний объём | 500-5000 сотрудников |

### 1.4. Субъекты

| Категория | Описание |
|-----------|----------|
| Работники организации | Сотрудники, проходящие обучение по охране труда |
| Члены комиссии | Председатель и члены комиссии по проверке знаний |
| Представитель профсоюза | Участвует в комиссии (опционально) |

### 1.5. Сроки хранения

| Тип данных | Срок | Обоснование |
|------------|------|-------------|
| Данные сотрудников (обучение) | Период работы + 3 года | Срок исковой давности |
| Журнал отправок | 5 лет | Требования Минтруда |
| Логи приложения | До 5 x 5MB ротация | Диагностика |
| Резервные копии | До 5 копий | Восстановление |
| Мастер-ключ | Весь срок эксплуатации | Необходим для расшифровки |

### 1.6. Автоматизированная обработка

Обработка **полностью автоматизирована**: все операции (импорт, хранение, экспорт, передача) выполняются без участия человека на уровне приложения.

## 2. Необходимость и пропорциональность

### 2.1. Правовое основание

| Основание | Применимость |
|-----------|-------------|
| 152-ФЗ ст.6 ч.2 п.1 | ✅ Обработка необходима для исполнения закона (Постановление №2464) |
| 152-ФЗ ст.6 ч.2 п.5 | ✅ Обработка необходима для исполнения трудового договора |
| ТК РФ ст.14, 86-90 | ✅ Обработка в целях охраны труда |
| Постановление №2464 пп. «е» п. 37 | ✅ Обязанность передавать сведения |

### 2.2. Достижение цели

Приложение необходимо для:
1. Исполнения обязанности работодателя по передаче данных в Минтруд
2. Контроля периодичности обучения
3. Формирования отчётности

### 2.3. Минимизация

- ✅ Собираются только поля, необходимые для передачи в Минтруд
- ✅ Нет биометрических данных
- ✅ Нет специальных категорий ПДн
- ✅ Нет данных о здоровье, судимости и т.д.
- ⚠️ Должность можно шифровать (желательно, но не критично)

### 2.4. Согласие

**Не требуется.** Обработка осуществляется на основании закона (ст.6 ч.2 152-ФЗ), а не на основании согласия субъекта. Работник не может отказаться от обработки, так как она необходима для исполнения обязанностей работодателя по ТК РФ и Постановлению №2464.

## 3. Риски для прав и свобод субъектов

### 3.1. Сценарии риска

**Сценарий 1: Утечка СНИЛС + ФИО**
- Вероятность: Средняя (3)
- Тяжесть: Средняя (3)
- Уровень: 9 (Средний)
- Последствия: идентификация субъекта, дискриминация при трудоустройстве, спам, фишинг
- Затронуто: до 100 000 субъектов

**Сценарий 2: Утечка данных об обучении**
- Вероятность: Средняя (3)
- Тяжесть: Низкая (2)
- Уровень: 6 (Низкий)
- Последствия: репутационный ущерб, раскрытие структуры организации
- Затронуто: до 100 000 субъектов

**Сценарий 3: Потеря доступа к данным**
- Вероятность: Низкая (2)
- Тяжесть: Высокая (4)
- Уровень: 8 (Средний)
- Последствия: невозможность отчитаться в Минтруд, штрафы
- Затронуто: организация (не субъекты)

**Сценарий 4: Несанкционированная отправка в Минтруд**
- Вероятность: Низкая (2)
- Тяжесть: Средняя (3)
- Уровень: 6 (Низкий)
- Последствия: неверные данные в реестре
- Затронуто: до 100 000 субъектов

**Сценарий 5: Компрометация мастер-ключа**
- Вероятность: Низкая (2)
- Тяжесть: Критичная (5)
- Уровень: 10 (Средний)
- Последствия: расшифровка всех ПДн
- Затронуто: до 100 000 субъектов

### 3.2. Матрица рисков

| Сценарий | Вер. (1-5) | Посл. (1-5) | Уровень | Категория |
|----------|-----------|-------------|---------|-----------|
| Утечка СНИЛС+ФИО | 3 | 3 | 9 Средний | Конфиденциальность |
| Утечка обучения | 3 | 2 | 6 Низкий | Конфиденциальность |
| Потеря доступа | 2 | 4 | 8 Средний | Доступность |
| Несанкц. отправка | 2 | 3 | 6 Низкий | Целостность |
| Компрометация ключа | 2 | 5 | 10 Средний | Конфиденциальность |

## 4. Меры по снижению рисков

### 4.1. Технические меры

| Риск | Мера | Эффективность |
|------|------|---------------|
| Утечка СНИЛС+ФИО | Полевое шифрование (Fernet AES-128-CBC) | Высокая |
| Утечка СНИЛС+ФИО | Windows DPAPI для защиты ключа | Высокая |
| Утечка СНИЛС+ФИО | SensitiveDataFilter в логах (27 паттернов) | Высокая |
| Утечка СНИЛС+ФИО | PRODUCTION MODE (блокировка insecure fallback) | Высокая |
| Компрометация ключа | HMAC integrity проверка ключа | Средняя |
| Компрометация ключа | PBKDF2 passphrase (600K итераций) | Высокая |
| Несанкц. отправка | Аудит SEND_XML с HMAC | Средняя |
| Потеря доступа | Автоматический backup (до 5 копий) | Высокая |
| Потеря доступа | Backup ключей (ZIP+PBKDF2) | Высокая |
| MiTM | TLS 1.2+ verify=True | Высокая |
| XXE-атака | defusedxml + LimitedXMLParser | Высокая |
| SQL-инъекция | Parameterized queries | Высокая |
| Несанкц. доступ | Session auto-lock (passphrase) | Средняя |

### 4.2. Организационные меры

| Риск | Мера |
|------|------|
| Все | Назначение ответственного за обработку ПДн |
| Все | Политика обработки ПДн |
| Все | Инструктаж операторов |
| Физический доступ | BitLocker, ограничение доступа к ПК |
| Антивирус | Microsoft Defender / Kaspersky |
| Обновления | Windows Update + ручное обновление ПО |
| Утечка | План реагирования на инциденты (см. security_checklist.md) |

## 5. Заключение

### 5.1. Вывод

Обработка персональных данных в приложении Excel_to_XML является **необходимой для исполнения законодательства РФ** (Постановление №2464, ТК РФ). Риски для прав и свобод субъектов ПДн **контролируются** следующими мерами:

1. **Криптографическая защита** — полевое шифрование, DPAPI, PBKDF2
2. **Аудит** — 32 события с HMAC integrity
3. **Безопасность разработки** — XXE защита, parameterized queries, secure temp
4. **Организационные меры** — политика, обучение, реагирование

### 5.2. Остаточные риски

| Риск | Принят? | Комментарий |
|------|---------|-------------|
| Memory dump | ✅ Принят | Требуется защита ОС (BitLocker, антиотладка) |
| Clipboard leakage | ⚠️ Частично | Рекомендовано: clipboard auto-clear |
| Cert pinning | ✅ Принят | Невозможно (сервер не предоставляет) |
| HSM | ✅ Принят | Требуется Enterprise-лицензия |

### 5.3. Пересмотр

Настоящая DPIA должна пересматриваться:
- **Ежегодно** — плановый пересмотр
- **При изменении** законодательства
- **При изменении** архитектуры обработки
- **При инциденте** утечки ПДн
